# 代码生成与文件组织规范

本文档仅约束项目根目录下的 `code/` 目录及其子目录。所有方法的新增或修改代码、测试、脚本和运行产物都必须遵守以下规则。

## 方法目录

- 每个方法必须位于独立的 `code/method-<name>/` 目录。
- `method-a`、未来的 `method-b` 等方法使用同构目录结构，彼此的代码、数据、模型权重和实验输出不得混放。
- 不在 `code/` 根目录直接放置某个方法的业务源代码、数据集、checkpoint 或实验输出。

## 文件分类

在每个 `code/method-<name>/` 下：

- `src/`：全部业务源代码和可复用模块。
- `tests/`：单元测试、集成测试和冒烟测试。
- `scripts/`：一次性诊断、数据处理和实验辅助脚本。
- `data/`：原始数据、仿真数据、拓扑数据及其他数据集文件。
- `checkpoint/`：模型参数、中间状态和训练过程中的可恢复文件，不是最终交付目录。
- `output/`：最终实验结果、图片、表格、报告和其他可交付产物。
- `logs/`：运行日志和调试日志。
- `main.py`：该方法的命令行或端到端入口（需要时创建）。
- `README.md`：该方法的运行方式、目录说明和已知限制（需要时创建）。
- `requirements.txt`：该方法的依赖清单（需要时创建）。

## 输出位置约束

- 代码不得将文件写入与其性质不匹配的目录。
- 最终交付结果必须从 `output/` 获取，不得从 `checkpoint/` 获取。
- 运行时生成的数据不得写入 `src/`、`tests/` 或 `scripts/`。
- 测试临时文件应写入测试框架提供的临时目录，不得污染源代码目录。

## 命名与一致性

- 方法目录使用 `method-<name>` 形式。
- 测试目录统一命名为 `tests/`；所有 README、计划和文档引用必须保持一致。
- 新增 Python 模块使用小写下划线命名；模块、测试和脚本的名称应能反映其职责。

## 适用边界

- 本文档不约束 `docs/`、`.githooks/` 或其他非 `code/` 目录的文件组织。
- 项目级 Git、文档和 Agent 行为规则由根 `AGENTS.md` 及 `docs/git-rules.md` 负责。
