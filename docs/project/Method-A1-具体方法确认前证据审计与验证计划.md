# Method-A1 具体方法确认前证据审计与验证计划

## 一、目的与范围

本文依据现有项目文档及 `code/method-a1/output/` 中保存的实验报告，审计当前研究命题的证据状态，并为尚未验证的内容制定后续验证计划。

本文只回答两个问题：

1. 哪些结论已经得到现有实验支持，以及这些结论成立的范围是什么；
2. 在确认因素分解、不变表示、差分表示或度量学习等具体方法之前，还需要完成哪些验证。

本文不预先选择具体模型，也不将代码实现完成、实验流程跑通或单次 smoke 成功等同于科学命题已经成立。

## 二、证据判定原则

本文采用以下三种证据状态。

### 2.1 已验证，但限定适用范围

同时满足以下条件时，相关命题记为已验证：

- 存在可读取的原始实验报告或逐样本结果；
- 实验对象、场景、样本量和指标定义明确；
- 结论没有超出实验实际覆盖的场景；
- 关键结论能够由现有报告字段直接复核。

“已验证”只对报告实际覆盖的 IEEE13、S0、数据版本、随机种子或对照范围成立，不自动外推到跨工况、跨拓扑或真实系统。

### 2.2 初步验证

流程已经运行并产生结果，但仅覆盖单一配置、少量样本、单一拓扑或 smoke 数据时，记为初步验证。该状态可以证明接口、数据契约和评价流程可运行，但不足以支持一般性方法结论。

### 2.3 未验证

仅在设计文档中提出、缺少有效对照、数据划分无效、样本条件不足或没有实际报告支撑的命题，记为未验证。

## 三、已经验证的内容

### 3.1 S0 条件下真实物理响应特征包含故障位置区分信息

正式 S0 Oracle separability 报告覆盖 153 个故障样本和 2448 个负候选对。报告显示：

- fault Oracle Top-1 为 1.0；
- 全候选 fault Oracle Top-1 为 1.0；
- 平均与中位真实候选排名均为 1；
- 错序候选对比例为 0；
- 存在错序候选的样本比例为 0。

因此，可以确认：

> 在当前 IEEE13、S0、全量观测和现有 OpenDSS 数据条件下，真实物理响应特征包含足以完成候选定位的信息。

该结论不能外推为所有工况、阻抗、观测率和拓扑条件下均可分。

证据来源：

- `code/method-a1/output/s0-spb50-rk/oracle-separability/oracle_separability.json`；
- `docs/project/Method-A1 新响应特征表示空间：问题动机（第一、第二部分）.md`。

### 3.2 S0 中大量候选的物理分离裕度较小

同一正式报告显示，all-candidate hardest-negative gap 的中位数约为：

```math
2.0365\times 10^{-4}.
```

其最小值约为：

```math
1.3041\times 10^{-4}.
```

以历史固定参考 margin 0.1 衡量，约 97.39% 的故障样本 gap 低于该参考值。

因此，可以确认：

> 当前 S0 中物理可分性确实存在，但相当一部分困难候选依赖较小的真实分离裕度。

该结论支持继续研究表示显著性和预测误差问题，但不能单独证明必须采用新的诊断空间。

### 3.3 当前模型与 S0 Oracle 上界之间存在显著差距

当前 S0 基线测试集包含 320 个样本，其中 153 个为故障样本。报告显示：

- 节点 Top-1 约为 0.3333；
- 节点 Top-K 约为 0.4902；
- 平均真实候选排名约为 3.6667；
- 检测准确率约为 0.8875；
- 故障召回率约为 0.8431；
- F1 约为 0.8776。

Oracle fault Top-1 为 1.0，而模型 fault Top-1 与其相差约 0.6667。因此，可以确认：

> 当前 S0 的主要性能损失发生在模型预测与候选排序环节，而不是因为真实物理响应完全不可分。

该结果尚不能进一步断言损失主要来自表示几何；预测器能力、训练目标、数据覆盖和距离定义仍可能共同造成该差距。

证据来源：

- `code/method-a1/output/s0-spb50-rk/report.json`；
- `code/method-a1/output/s0-spb50-rk/oracle-separability/oracle_separability.json`。

### 3.4 Z 路线一当前默认配置没有改善核心的相对可辨识性

seed 42、43、44 的完整运行均保持 Oracle fidelity，但三个随机种子的 `rho_Z` 中位数都高于对应的 `rho_S` 中位数：

- seed 42：`rho_S≈2.9427`，`rho_Z≈2.9708`；
- seed 43：`rho_S≈2.4247`，`rho_Z≈2.4333`；
- seed 44：`rho_S≈2.8161`，`rho_Z≈2.8318`。

虽然三个种子的 Z 空间节点 Top-1 均比各自 S 空间高约 0.0065，但 `rho` 均发生恶化，且 `rho_Z≤rho_S` 的样本比例仅约为 0.084、0.141 和 0.094。

因此，可以确认：

> 路线一当前默认配置能够保持 S0 Oracle 排序和结构安全门，但没有改善预先定义的核心 `rho` 指标，不能认定为有效诊断空间。

报告中的 `test_gates.passed=true` 只表示有限损失、Oracle fidelity、输入一致性、方差和能量等安全门通过，不表示方法有效性门已经通过。

证据来源：

- `code/method-a1/output/z-route1/z_report.json`；
- `code/method-a1/output/z-route1-seed43/z_report.json`；
- `code/method-a1/output/z-route1-seed44/z_report.json`。

### 3.5 单独使用 `R=Pr(rho_Z≤rho_S)` 不能证明表示改善

现有扫描已经验证：

- identity 对照的 `R=1.0`，但 `rho` 没有实际改善；
- random 对照的 `R≈0.919`，随机扰动也能产生较高 R；
- label-shuffle 对照的 `R≈0.966`，且得到最大的表面 `Δrho`；
- 25 组扫描配置及 3 组完整运行合计 28 份报告中，没有配置同时满足 `Δrho>0`、误差变化优于分离裕度变化、优于随机与标签置换对照、Oracle 保真且绝对 `rho` 不恶化。

因此，可以确认：

> 高 R 可能由恒等关系、随机扰动、全局缩放或错误监督产生，R 不能作为路线有效性的单一判据；当前参数扫描没有发现真实有效的路线一配置。

证据来源：

- `docs/project/Method-A1-Z路线一-参数扫描与对照结果.md`；
- `code/method-a1/output/z-sweep-g1/sweep_summary.json`；
- `code/method-a1/output/z-sweep-g2/sweep_summary.json`；
- `code/method-a1/output/z-sweep-g3/sweep_summary.json`。

### 3.6 响应特征库和 S0–S4 Oracle 分析流程已经能够运行

现有 `a1-signed-library-seed42` 保存了 64 个基础样本、16 个节点、17 个候选、12 个时间点和 6 个 Re/Im 标准化通道，并具有数组级校验值、真实拓扑、观测拓扑、观测掩码、故障参数和运行工况标识。

S0–S4 Oracle smoke 均产生了汇总、逐样本、hardest-negative 和图形结果。因此，可以确认：

> 响应特征库持久化、校验、场景视图派生和 Oracle 汇总流程具备可执行性。

该结论属于工程流程验证，不等同于 S1–S4 的模型鲁棒性或跨场景科学结论已经成立。

## 四、仅得到初步验证的内容

### 4.1 S1 的真实物理 Oracle 结果不受观测拓扑视图直接影响

S1 smoke 使用 10% 随机拓扑翻转、64 个样本，并保持由真实拓扑 `G*` 生成响应特征。其 Oracle Top-1 与 S0 均为 1.0，hardest-negative gap 也与 S0 相同。

这只能说明：

> 当前实现正确地区分了响应生成拓扑 `G*` 与模型观测拓扑 `G_obs`，Oracle 计算没有被错误拓扑视图污染。

它不能说明模型在错误拓扑输入下仍然稳健，因为该 Oracle 计算没有使用预测模型。

### 4.2 S2 的单一 50% 随机观测视图仅形成流程级证据

S2 smoke 在 50% retention rate、单一随机掩码设置下，对 64 个样本得到 Oracle Top-1 1.0，hardest-negative gap 中位数约为 `2.1932×10^-4`。

这只能初步说明当前 masked residual 流程在该视图下仍能工作。它不能证明不同观测率、不同掩码种子、关键节点方案或极低观测率下均可分，也不能证明模型在部分观测下具备稳定的故障检测、候选定位或拒识能力。因此，S2 尚未得到正式验证。

### 4.3 S4 高阻子集的单一 Oracle smoke 仅形成流程级证据

S4 smoke 使用高阻档 `z_fault≥50Ω`，包含 21 个故障样本，没有正常样本。Oracle Top-1 为 1.0，hardest-negative gap 中位数约为 `1.7772×10^-4`，低于同批 S0 smoke 的约 `2.3163×10^-4`。

这为“高阻条件可能缩小候选分离裕度”提供了初步迹象，但由于样本较少、没有正常样本、没有跨阻抗配对统计，也没有模型端到端结果，尚不能证明阻抗升高会系统性压缩物理裕度，亦不能证明模型能够区分高阻故障与正常状态。因此，S4 尚未得到正式验证。

### 4.4 物理邻近性只得到弱且不稳定的初步证据

当前 proximity smoke 使用 64 个样本、32 个故障样本、16 个节点和单一 IEEE13 拓扑。结果显示：

- 拓扑跳数与响应特征距离的 Spearman 相关约为 0.354；
- 电气距离相关约为 0.137；
- 结构距离相关约为 -0.221；
- 20 次置换的 Mantel 检验均未得到显著结果；
- 响应特征最近邻为一跳邻居的比例为 0.4375；
- 最近邻平均拓扑距离为 2.0，随机基线约为 3.5167。

因此，当前只能确认分析流程能够运行，并存在需要继续检验的弱趋势。不能把“拓扑邻近等于响应相似”写成已经验证的物理约束。

证据来源：

- `code/method-a1/output/proximity/smoke-20260910-final/proximity.json`。

## 五、尚未验证的关键命题

### 5.1 目标工况与观测条件下的故障信息是否充分

S0 的现有 Oracle 结果只能支持特定 IEEE13 数据范围内的可分性。尚未系统比较 physical gap 与测量噪声、数值误差和重复仿真误差，也不能将 S0 结论外推至 S2、S4 及组合场景。因此，目标条件下的实际信息充分性仍待验证。

### 5.2 原始响应特征距离是否由故障、工况和其他因素共同主导

当前已有多工况标识和全候选响应特征库，但没有正式的方差分解、配对距离比较或跨环境稳定性报告。因此，尚未证明非故障因素对距离的影响达到需要专门处理的程度。

### 5.3 故障因素与工况因素是否能够被显式识别

当前没有证明公共运行状态与候选故障扰动可以唯一或稳定分解。路线二文档明确指出，现有 S0 数据不足以证明分解可辨识。

### 5.4 应采用显式因素识别、条件不变表示还是二者结合

当前没有在相同数据、相同预测器、相同计算预算和相同评价协议下比较这三种思想。因此，尚不能确认方法类型。

### 5.5 诊断几何是否是当前性能瓶颈

S0 已经证明预测结果与 Oracle 存在显著差距，路线一失败也说明一种几何重组没有解决问题。但是，目前缺少 predictor-only、固定无学习变换和冻结预测器的表示变换对照，无法分离预测器误差与距离几何的贡献。

### 5.6 哪些物理关系可以作为训练约束

当前尚未验证以下关系能够跨工况和跨拓扑稳定成立：

- 拓扑邻近与响应相似关系；
- 电气距离与故障混淆关系；
- 故障严重程度或阻抗变化的单调关系；
- hardest-negative 候选排序的跨工况稳定性；
- 局部邻域关系的跨拓扑可迁移性。

### 5.7 S1–S4 条件下模型端到端性能

现有 S1–S4 结果主要是 Oracle smoke。尚未验证模型在以下条件下的预测与诊断能力：

- 不同类型和不同强度的拓扑错误；
- 不同观测率与不同掩码方案；
- 未见拓扑实例和拓扑族；
- 高阻故障与 S1–S3 的组合场景；
- 正常样本与弱故障之间的误报、漏报和不确定性。

其中，S3 smoke 报告明确给出 `split_valid=false`，原因是当前只有一个拓扑组，无法形成互斥训练测试划分。因此，跨拓扑泛化尚未得到任何有效验证。

### 5.8 真实数据、跨馈线泛化和不确定性校准

当前没有真实系统数据验证，也没有 IEEE37、IEEE123 或其他馈线上的正式模型结果。检测阈值仍未通过验证集正式标定，ROC-AUC、概率校准和证据不足时的拒识能力尚未验证。

## 六、待验证命题与验证实验的对应关系

本节采用“一个实验可以检验多个明确命题，但每项结论必须回溯到具体实验”的原则。实验报告必须列出所对应的命题编号；没有对应实验编号的结果，不得用于支持方法选择。

### 6.1 信息充分性、原始距离与因素可辨识性

1. **命题 H0：在目标工况和观测条件下，真实物理响应包含高于噪声边界的故障区分信息。**
   - 对应实验：`E0-Oracle 信息充分性与噪声边界实验`。
   - 实验操作：在控制工况、观测条件和候选集合后，使用真实物理响应进行全候选 Oracle 排序，并估计测量噪声、数值误差和重复仿真误差。
   - 主要证据：Oracle Top-1、Top-K、候选错序率、hardest-negative physical gap、gap 相对噪声比及不可分候选对。
   - 可支持结论：当前观测是否包含达到实际可利用量级的故障区分信息，以及结论成立的场景边界。
   - 不可支持结论：Oracle 可分不能证明预测器有效，也不能证明诊断几何是性能瓶颈。

2. **命题 H1：原始响应特征距离受到故障因素与非故障因素的共同影响，且非故障因素足以改变候选排序。**
   - 对应实验：`E1-配对因素来源实验`。
   - 实验操作：分别构造相同故障不同工况、不同故障相同工况、相同故障与工况但不同噪声或观测视图等配对。
   - 主要证据：配对距离分布、`R_mix`、方差贡献、候选排序翻转率及其 bootstrap 置信区间。
   - 可支持结论：非故障因素是否达到必须专门处理的程度。
   - 不可支持结论：仅凭该实验不能判断应采用显式因素识别还是不变表示学习。

3. **命题 H2：故障因素与工况因素在现有干预数据下具有可辨识条件。**
   - 对应实验：`E2-故障与工况干预对照实验`。
   - 实验操作：比较同一工况下的故障增量 `Delta_F` 与无故障条件下的工况增量 `Delta_C`，并在留出工况上复核方向稳定性。
   - 主要证据：子空间重叠程度、跨工况方向一致性、故障与工况探针结果、标签置换基线。
   - 可支持结论：是否具备采用显式因素识别的必要数据条件。
   - 不可支持结论：探针准确率本身不能证明因素被唯一恢复。

4. **命题 H3：显式因素识别、条件不变表示或二者结合中的某一路线更适合当前问题。**
   - 对应实验：`E3-统一协议方法思想对照实验`。
   - 实验操作：在相同数据划分、预测器、计算预算和评价协议下比较三类方法思想。
   - 主要证据：跨工况诊断指标、残余工况可预测性、故障信息保持程度、跨种子稳定性。
   - 可支持结论：具体方法思想的相对适用性。
   - 前置条件：只有 `E1` 证明非故障影响不可忽略后，`E3` 的比较才构成必要的方法选择证据。

### 6.2 诊断几何瓶颈与物理约束

1. **命题 H4：诊断几何是独立于预测器能力的性能瓶颈。**
   - 对应实验：`E4-预测器与几何瓶颈归因实验`。
   - 实验操作：比较原始空间、predictor-only、固定无学习变换、冻结预测器后学习表示、联合训练及零假设对照。
   - 主要证据：`delta`、`e`、`rho`、候选错序率、Oracle fidelity 及模型 Top-K 的成对变化。
   - 可支持结论：是否有必要引入新的诊断空间。
   - 不可支持结论：单次 Z 空间 Top-1 改善或单一 `R` 指标不能证明 H4。

2. **命题 H5：某一物理关系稳定到足以作为训练约束。**
   - 对应实验：`E5-跨工况跨拓扑物理关系复核实验`。
   - 实验操作：在多个工况、多个拓扑实例及至少两个拓扑族上，独立检验拓扑距离、电气距离、局部邻域、候选排序及阻抗单调关系。
   - 主要证据：以拓扑实例为统计单位的效应量、置信区间、置换检验及独立拓扑复核。
   - 可支持结论：哪一条经过验证的物理关系可以进入 `L_physical`。
   - 不可支持结论：现有单拓扑 proximity smoke 不能支持 H5。

### 6.3 S1 与 S3 场景命题

1. **命题 H6-S1：模型对不同类型和强度的观测拓扑错误具有可量化鲁棒性。**
   - 对应实验：`E6-S1-拓扑错误端到端压力实验`。
   - 主要证据：不同 flip、missing 与错误率下的 Oracle、模型定位、检测和拓扑异常识别结果。

2. **命题 H6-S3：模型能够泛化到未参与训练的拓扑实例或拓扑族。**
   - 对应实验：`E6-S3-互斥拓扑划分泛化实验`。
   - 主要证据：`split_valid=true` 的分组划分、逐拓扑结果、拓扑均值和最差拓扑结果。
   - 结论边界：当前 `split_valid=false` 的 smoke 不构成 H6-S3 的任何正向证据。

### 6.4 S2 部分观测的补充验证对应关系

现有 50% 单掩码 smoke 只证明流程可运行。S2 的正式结论必须分别由以下实验支持。

1. **命题 H6-S2-A：在目标观测率和观测方案下，真实响应仍保留候选区分信息。**
   - 对应实验：`E6-S2.1-观测率与掩码方案 Oracle 曲线实验`。
   - 实验操作：覆盖 full、key-node 和 random mask，以及 10%、30%、50%、70% 和 100% retention rate。
   - 主要证据：Oracle Top-1、Top-K、hardest-negative gap、候选错序率和不可分候选对。
   - 可支持结论：部分观测是否造成信息层面的不可辨识。

2. **命题 H6-S2-B：S2 的物理可分性结论不依赖单一随机掩码。**
   - 对应实验：`E6-S2.2-跨掩码种子稳定性实验`。
   - 实验操作：每个观测率和方案使用多个独立掩码种子，并按关键节点是否被观测分层。
   - 主要证据：Oracle gap 和候选排名的跨种子分布、最差掩码结果及置信区间。
   - 可支持结论：S2 Oracle 结论是否对掩码实现稳定。

3. **命题 H6-S2-C：模型在部分观测下仍具备端到端诊断能力，并能在证据不足时拒识。**
   - 对应实验：`E6-S2.3-部分观测模型与拒识实验`。
   - 实验操作：在与 `E6-S2.1` 相同的观测条件下，同时纳入故障与正常样本，比较原模型和候选方法。
   - 主要证据：故障召回、正常误报、候选排名、校准误差、风险—覆盖曲线和不确定率。
   - 可支持结论：模型端 S2 鲁棒性及拒识有效性。
   - 结论边界：`E6-S2.1` 和 `E6-S2.2` 的 Oracle 结果不能替代本实验。

### 6.5 S4 高阻故障的补充验证对应关系

现有高阻子集 smoke 样本较少且没有正常样本，只能作为提出假设的依据。S4 的正式结论必须分别由以下实验支持。

1. **命题 H6-S4-A：阻抗升高会系统性压缩故障候选的物理分离裕度。**
   - 对应实验：`E6-S4.1-跨阻抗配对 Oracle 实验`。
   - 实验操作：对相同故障位置、类型、工况和拓扑生成低阻、中阻与高阻配对样本，只改变故障阻抗。
   - 主要证据：配对 physical gap 变化、单调性比例、低分位数、候选错序率及成对置信区间。
   - 可支持结论：高阻与物理裕度之间是否存在稳定关系。

2. **命题 H6-S4-B：在目标高阻范围内，真实响应仍保留足够的故障定位与故障检测信息。**
   - 对应实验：`E6-S4.2-高阻 Oracle 充分性与正常状态对照实验`。
   - 实验操作：每个阻抗档同时纳入故障和正常样本，并加入仿真重复误差与测量噪声基线。
   - 主要证据：Oracle 定位指标、故障—正常分离、gap 相对噪声比、不可分样本比例。
   - 可支持结论：高阻条件下的信息充分性边界。

3. **命题 H6-S4-C：模型能够区分高阻故障与正常状态，并对弱证据进行校准或拒识。**
   - 对应实验：`E6-S4.3-高阻模型检测与校准实验`。
   - 主要证据：按阻抗分层的漏报率、正常误报率、候选排名、校准误差、风险—覆盖曲线和不确定率。
   - 可支持结论：模型端 S4 检测、定位及不确定性表现。
   - 结论边界：高阻 Oracle Top-1 为 1.0 不能替代本实验。

4. **命题 H6-S4-D：高阻故障结论在拓扑错误、部分观测和跨拓扑条件下仍然成立。**
   - 对应实验：`E6-S4.4-S4 组合场景交互实验`。
   - 实验操作：分别验证 S1+S4、S2+S4 和 S3+S4，并设置相应的单因素对照。
   - 主要证据：交互项效应、最差场景的 physical gap、`rho`、漏报率、误报率和不确定率。
   - 可支持结论：S4 是否与其他困难条件产生额外退化。

### 6.6 阈值、真实数据与最终外推

1. **命题 H7：检测阈值、不确定性输出和真实系统外推具有有效依据。**
   - 对应实验：`E7-阈值校准与独立数据验证实验`。
   - 主要证据：独立验证集阈值、ROC-AUC、PR-AUC、校准误差、风险—覆盖曲线，以及真实数据或独立高保真数据结果。
   - 结论边界：在完成 `E7` 前，不宣称真实系统泛化能力。

## 七、验证计划

本节按问题类型组织验证模块，小节编号不表示实验执行先后。正式执行顺序以第八节为准，其中 `E0` 必须在 `E1`–`E5` 及学习型方法比较之前完成。

### 7.1 验证模块 0：固定变量定义、假设和评价协议

#### 目标

避免在实验结果出现后重新定义“故障因素”“工况因素”或成功标准。

#### 工作内容

在数据契约中明确：

- 故障变量 `F`：故障位置、故障类型和故障阻抗；
- 条件变量 `C`：负荷、分布式电源出力、运行点和真实拓扑；
- 观测变量 `O`：观测节点、观测时间点和观测掩码；
- 干扰变量 `N`：测量噪声、无关背景扰动及不可信观测拓扑；
- 交互项：故障与工况、阻抗与观测条件、故障与拓扑之间的联合影响。

真实拓扑既可能是决定物理响应的条件变量，也可能在台账错误场景中表现为模型无法获得的隐变量，因此必须分别记录 `G*` 和 `G_obs`，不能统一归入“应删除的非故障因素”。

正式实验开始前固定：

- 训练、验证和测试按运行工况及拓扑实例分组，禁止同一基础样本的派生视图跨集合泄漏；
- 所有方法共享同一响应特征库、预测器初始化、候选集合、掩码和评价脚本；
- 至少保留 identity、random、label-shuffle、candidate permutation 和 predictor-only 对照；
- 主要指标为 Oracle Top-1、hardest-negative `delta`、预测误差 `e`、`rho=e/(delta+epsilon)`、候选错序率和跨视图排名稳定性；
- 次要指标为 Top-1、Top-K、真实候选排名、检测指标、校准指标和不确定率；
- 正式样本量依据 pilot 的效应量和 bootstrap 置信区间宽度确定，不以 64 个 smoke 样本作为正式样本量。

#### 完成标准

形成唯一的数据划分文件、指标定义文件、随机种子集合和验收规则；后续方法不能单独修改这些条件。

### 7.2 验证模块 1：验证原始距离是否混合多种因素

#### 实验设计

对应实验编号：`E1-配对因素来源实验`；验证命题：H1。

使用 OpenDSS 构造故障与工况交叉的数据设计。对每个固定运行工况生成全部故障候选，使同一工况下可以比较不同故障；同时对每个固定故障候选收集多个运行工况，使同一故障下可以比较不同工况。

需要构造以下配对：

1. 相同故障、不同工况；
2. 不同故障、相同工况；
3. 相同故障和工况、不同噪声或观测视图；
4. 不同故障和工况；
5. 无故障、不同工况。

所有比较应控制故障类型和阻抗，随后再分别分析故障类型及阻抗交互。

#### 分析指标

计算：

- 各类配对的原始距离分布；
- 同故障跨工况距离与同工况跨故障距离的比值；
- 故障、工况、拓扑、阻抗和交互项对响应特征变化的方差贡献；
- 在改变工况而保持故障不变时，最近候选和 hardest-negative 排名发生变化的概率；
- 各结论的按基础样本 bootstrap 置信区间。

可定义辅助指标：

```math
R_{mix}
=
\frac{
\operatorname{median}d(S_{F,C_1},S_{F,C_2})
}{
\operatorname{median}d(S_{F_1,C},S_{F_2,C})
}.
```

该比值只用于描述工况变化相对于故障变化的量级，不能脱离候选错序率和方差贡献单独判定。

#### 决策规则

- 如果工况和干扰因素对距离及候选排序的影响可忽略，则不把因素处理作为首要方法需求；
- 如果其影响显著且会改变候选排序，则在 `E0` 通过后执行因素可辨识性模块，研究显式因素识别或条件不变表示；
- 如果影响主要来自观测噪声而非工况，则优先研究去噪、观测建模和不确定性，而不是因素分解。

### 7.3 验证模块 2：验证故障信息的充分性与因素可辨识条件

#### 故障信息充分性验证

对应实验编号：通用验证使用 `E0-Oracle 信息充分性与噪声边界实验`，验证 H0；S2 使用 `E6-S2.1` 和 `E6-S2.2`，S4 使用 `E6-S4.1` 和 `E6-S4.2`，分别验证 H6-S2-A、H6-S2-B、H6-S4-A 和 H6-S4-B。

在 S0、S2、S4 及其组合条件下重新计算完整 Oracle 曲线，包括：

- Oracle Top-1、Top-K 和候选错序率；
- hardest-negative gap 的中位数、低分位数和最小值；
- gap 相对于数值误差、测量噪声和重复仿真误差的比例；
- 按故障类型、阻抗、工况、观测率和拓扑分层的结果；
- 不可分候选对和并列候选对清单。

如果某些条件下不同故障的响应分布无法区分，则该部分不能通过表示变换解决，应增加观测、调整候选粒度或输出候选集合与不确定性。

#### 因素可辨识性验证

对应实验编号：`E2-故障与工况干预对照实验`；验证命题：H2。若 H1 和 H2 的结果表明有必要进一步比较方法思想，则执行 `E3-统一协议方法思想对照实验`，验证 H3。

利用仿真器提供的成对干预构造：

```math
\Delta_F=S(F,C)-S(\mathrm{NO\_FAULT},C),
```

```math
\Delta_C=S(\mathrm{NO\_FAULT},C_1)-S(\mathrm{NO\_FAULT},C_2).
```

检验：

- 故障扰动方向在不同工况下是否稳定；
- 工况变化方向与故障变化方向是否高度重叠；
- 在留出运行工况后，故障信息是否仍能被稳定预测；
- 在控制故障后，工况信息是否仍可被识别；
- 标签置换后上述结果是否回到随机水平。

探针模型只能作为必要证据，不能单独证明真实因素已经唯一恢复。显式因素识别还必须依赖交叉数据、物理干预或明确结构约束。

#### 决策规则

- 故障与工况方向稳定可区分，且研究要求解释性时，允许进入显式因素识别路线；
- 无法唯一分解，但跨环境存在稳定故障预测关系时，优先条件不变表示；
- 只能识别部分关键因素时，采用部分显式识别与条件不变表示结合；
- 故障和工况始终共变且无法建立交叉样本时，先补充数据，不确认任何分解方法。

### 7.4 验证模块 3：分离预测器瓶颈与诊断几何瓶颈

#### 对照设计

对应实验编号：`E4-预测器与几何瓶颈归因实验`；验证命题：H4。

在相同数据划分、相同训练预算和相同预测器初始权重下比较：

1. 原始 S 空间基线；
2. predictor-only：只调整预测器，不引入新空间；
3. 固定无学习变换：标准化、白化和具有物理参考的差分表示；
4. 冻结预测器，只学习诊断空间；
5. 预测器与诊断空间联合训练；
6. identity、random、label-shuffle 和 candidate permutation 对照。

#### 评价方式

每种设置同时报告：

- `delta_S/delta_Z`；
- `e_S/e_Z`；
- `rho_S/rho_Z`；
- 候选错序率和 hardest-negative 错序率；
- S 与 Z 的 Oracle 排序一致性；
- 模型 Top-1、Top-K 和真实候选排名；
- 表示方差、能量比和跨种子波动。

需要采用成对 bootstrap 或其他适合逐样本配对的统计检验，并报告效应量和置信区间，不能只报告单次均值。

#### 决策规则

- 如果 predictor-only 已取得主要改善，而学习几何没有提供超出 predictor-only 和固定变换的收益，则优先改进预测器；
- 如果固定差分或白化即可改善，优先采用简单、可解释的固定表示；
- 只有当学习表示在多随机种子下稳定改善 `rho`，显著优于 predictor-only 与所有零假设对照，并保持 Oracle fidelity 时，才确认诊断几何学习的必要性；
- 如果所有变换均不能改善，则保留 S 空间诊断，不继续扩大表示模型容量。

### 7.5 验证模块 4：验证可以作为约束的物理关系

#### 实验设计

对应实验编号：`E5-跨工况跨拓扑物理关系复核实验`；验证命题：H5。

在多个运行工况、多个拓扑实例和至少两个拓扑族上，分别检验：

- 拓扑跳数与响应特征距离的关系；
- 电气距离与响应特征距离的关系；
- hardest-negative 是否稳定集中在物理邻近区域；
- 故障阻抗或严重程度变化是否产生稳定的单调关系；
- 相同候选在不同工况下的局部邻域和排序是否稳定。

#### 统计要求

- 距离矩阵检验增加到足够的置换次数，并报告 Monte Carlo 误差；
- 以拓扑实例为统计单位进行 bootstrap，避免把同一拓扑的大量节点对当作独立样本；
- 按故障类型、阻抗、工况和拓扑族分层；
- 同时报告效应方向、效应量、置信区间和多重比较修正结果；
- 在未参与约束选择的拓扑上进行复核。

#### 决策规则

只有满足以下条件的关系才能写入 `L_physical`：

- 有明确物理机制或方程依据；
- 在独立拓扑和工况上方向一致；
- 效应量达到预先设定的诊断相关阈值；
- 加入约束后不会降低 Oracle 可分性或删除高阻故障的弱响应。

未满足上述条件的距离、邻域或排序只能作为描述性分析，不能作为强制训练约束。

### 7.6 验证模块 5：完成 S1–S4 端到端压力测试

#### S1：错误拓扑

对应实验编号：`E6-S1`；验证命题：H6-S1。

- 分别验证 flip 和 missing；
- 固定 0%、2%、5%、10% 和 30% 的错误率语义及取整规则；
- 同时报告 Oracle、原模型和候选方法；
- 检查全部残差是否同步升高、排序是否改变以及模型能否识别拓扑上下文异常。

#### S2：部分观测

对应实验编号：`E6-S2.1`、`E6-S2.2` 和 `E6-S2.3`；分别验证 H6-S2-A、H6-S2-B 和 H6-S2-C。

- 分别验证 full、key-node 和 random mask；
- 覆盖 10%、30%、50%、70% 和 100% retention rate；
- 每个观测率使用多个独立掩码种子；
- 分开报告故障召回、正常误报、候选排名和证据不足时的拒识结果。

#### S3：跨拓扑

对应实验编号：`E6-S3`；验证命题：H6-S3。

- 先生成至少能够形成有效互斥划分的多个拓扑实例和拓扑族；
- 按 `topology_id` 或 `topology_family` 分组划分，禁止同一拓扑泄漏；
- 报告每个测试拓扑、拓扑均值和最差拓扑结果；
- `split_valid` 必须为 true，否则不生成跨拓扑结论。

#### S4：高阻及组合场景

对应实验编号：`E6-S4.1`、`E6-S4.2`、`E6-S4.3` 和 `E6-S4.4`；分别验证 H6-S4-A、H6-S4-B、H6-S4-C 和 H6-S4-D。

- 固定低阻、中阻和高阻的范围与样本配额；
- 每个阻抗档同时包含故障和正常样本；
- 验证 S0+S4、S1+S4、S2+S4 和 S3+S4；
- 重点报告 physical gap、`rho`、漏报率、无故障误报率和不确定率。

#### 统一要求

正式结论至少应覆盖多个随机种子。随机种子数量由 pilot 方差和目标置信区间宽度确定；三个种子可作为最低诊断性重复，但不能替代跨拓扑和跨工况独立重复。

### 7.7 验证模块 6：阈值、不确定性和真实数据验证

对应实验编号：`E7-阈值校准与独立数据验证实验`；验证命题：H7。

在候选方法通过 S0–S4 后，再进行：

- 使用验证集标定故障检测阈值；
- 报告 ROC-AUC、PR-AUC、校准误差和风险—覆盖曲线；
- 设计证据不足时的拒识规则；
- 使用真实数据或独立高保真仿真数据检验仿真偏差；
- 在未参与方法选择的馈线和运行周期上完成最终验证。

在完成该验证模块之前，不宣称方法具备真实系统泛化能力。

## 八、推荐执行顺序

建议按照以下顺序推进：

1. 固定变量、数据划分、指标和零假设对照；
2. 使用 `E0` 验证故障信息充分性及其相对于噪声和误差的边界；
3. 使用现有 IEEE13 响应特征库完成 `E1` 多因素混合 pilot，并根据效应量扩充交叉工况数据；
4. 使用 `E2` 验证因素可辨识条件，仅在必要时通过 `E3` 比较因素处理方法思想；
5. 使用 `E4` 区分数据、噪声、预测器、校准和独立距离结构瓶颈；
6. 仅在独立距离结构瓶颈成立时比较固定变换与学习型诊断空间；
7. 使用 `E5` 在独立数据上筛选能够进入损失函数和验收规则的物理约束；
8. 完成 S1–S4 端到端压力测试；
9. 最后确认最小有效方法，并进行阈值、不确定性及真实数据验证。

## 九、具体方法的最终选择规则

验证完成后，按照以下规则确定方法方向：

- 如果非故障因素对距离和候选排序影响很小，则不优先引入因素分解或不变表示，先改进预测器；
- 如果非故障因素影响显著且来源可辨识，则选择显式因素识别或显式识别与条件不变表示的组合；
- 如果非故障因素影响显著但无法唯一分解，而跨环境稳定关系存在，则选择条件不变表示；
- 如果故障信息充分且距离几何被证明是独立瓶颈，则选择受物理约束的诊断几何学习；
- 如果固定差分已经达到同等效果，则优先采用固定差分，不增加学习映射；
- 如果所有表示方法均未超过 predictor-only 和零假设对照，则保留原 S 空间，并将研究重点转向预测器、数据和观测条件；
- 只有经过独立验证的物理关系可以作为训练约束，未经验证的原始距离和邻域不得直接固化。

## 十、计划产物

每个验证模块应至少输出：

- 完整实验配置及数据版本；
- 可复核的逐样本结果；
- 主要指标及 bootstrap 置信区间；
- 按故障类型、工况、阻抗、观测率和拓扑分层的报告；
- identity、random、label-shuffle、candidate permutation 和 predictor-only 对照；
- 通过或未通过相应决策门的明确结论；
- 已知局限及不允许外推的范围。

所有最终实验报告必须写入 `code/method-a1/output/`。文档只记录稳定结论和证据索引，不以 `checkpoint/` 或单次日志作为最终证据。

## 十一、当前结论

现有证据已经足以确认三个事实：

1. 当前 IEEE13 S0 物理响应特征具有 Oracle 可分性，但困难候选的物理裕度较小；
2. 当前模型与 Oracle 上界之间存在明显差距；
3. 路线一当前实现及既有参数扫描没有改善核心 `rho`，不能作为已经有效的方法。

现有证据尚不足以确认：原始距离是否由非故障因素主导、故障与工况是否可显式分解、诊断几何是否是主要瓶颈，以及哪些物理关系可以作为可靠约束。

因此，下一步不应直接确认新的模型结构，而应先使用 `E0` 确认信息充分性与噪声边界，再执行 `E1` 至 `E5`，完成多因素影响、可辨识条件、瓶颈归因和物理约束验证。S2 与 S4 还必须分别完成第 6.4 节和第 6.5 节所列实验，现有 smoke 结果不得被引用为模型鲁棒性或一般可分性的正式证据。只有这些前提成立后，具体方法选择才具有充分依据。
