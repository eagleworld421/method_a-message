# Method-A1 新投影空间 Z：可行性分析

## 1. 共同成立条件

三个方案都要求：真实 signature 可稳定生成；候选与观测具有一致的通道、时间和节点语义；掩码能区分缺失与零值；训练数据覆盖足够运行工况；Oracle residual 排序可复现；评价能够逐样本计算 `δ`、`e` 和 `ρ`。

此外，若采用路线 A，必须证明 `d_Z` 仍能解释候选对观测的物理一致性；若只能证明改善预测而不能证明诊断语义，则只能采用路线 B。

## 2. 方案一可行性

前提是存在低容量、稳定的共享映射，并且其变换不会破坏 Oracle 排序。现有框架已满足输入张量、签名 bank、masked MSE 和统一候选比较的基础条件，但当前 `signature_predictor.py` 含 candidate embedding，需在 Z 实验中隔离或移除该旁路，避免把候选索引混入物理映射。

需要新增的最小内容：共享 Eθ、Z 距离、Oracle-Z 评估、坍缩检查和 `ρ_Z` 报告。TCN、GNN、数据生成逻辑可保持不变。方案一与 S1–S4 兼容性最高。

## 3. 方案二可行性

前提是公共状态和候选扰动在数据中可辨识，且 `c(S)` 不携带候选标签。当前 S0 样本数量和运行工况覆盖不足以证明这一点；S1–S4 中真实拓扑、观测掩码和阻抗档位还需先形成统一数据契约。

需要增加公共状态定义、分解重构损失、分解消融和跨工况稳定性检查。若分解导致 Oracle Top-1 下降，应立即降级为分析工具，不能作为诊断空间。

## 4. 方案三可行性

前提是存在不依赖候选 ID 的可信 `S_ref`。若使用物理基线或同一运行状态的正常响应，方案三可在现有框架中低成本实现；若参考来自全候选集合，则必须证明不会泄漏测试候选信息。

方案三几乎不需改变 TCN/GNN，只需在评估和损失前增加固定变换。它最适合作为零学习基线，用来判断“重新坐标化”本身是否改善 hardest-negative 的 `ρ`。

## 5. 与原有前提的兼容性

兼容部分：S_k 的反事实物理定义、真实拓扑监督、候选/观测同空间、masked residual、Oracle 排序约束。

需要补充部分：Z 的可比距离契约；S1 的 `G*`/`G_obs` 双拓扑元数据；S2 的完整 signature 与观测掩码分离；S3 的拓扑族划分；S4 的阻抗档位和不确定性指标；统一的多种子、多工况验证协议。

当前 S0 只能证明物理信息存在，不能证明任一方案在 S1–S4 有效。

## 6. 分阶段验收

阶段一：固定差分基线，确认候选/观测同映射且 Oracle Top-1 不下降。

阶段二：受限共享映射，比较 `ρ_Z` 与 `ρ_S`，同时检查输出方差和误差放大。

阶段三：加入多工况、S1–S4，并按故障类型、拓扑距离、观测率、拓扑错误率和阻抗档位分层报告。

硬门槛包括：`Oracle Top-1_Z=Oracle Top-1_S`；hardest-negative `ρ_Z` 显著下降或至少不恶化；正常样本误报率不恶化；无坍缩；结果在多种子下稳定。

## 7. 失败回退

若 Oracle 排序被破坏，回退到 S 空间诊断；若 Z 只改善预测误差但不具备解释性，采用路线 B；若 `ρ` 不改善，保留当前 S0 基线并优先调整预测器、采样和 margin，而不是继续扩大 Z 模型容量。
