# 路线二：公共状态与候选特有扰动分解

## 一、目标与核心思想

将 signature 中由负荷、分布式电源和运行点造成的公共成分，与故障候选产生的特有扰动分开，使诊断距离更关注根因相关变化。

## 二、技术路线

对每个单独 signature 估计公共状态描述 `c(S)`，再生成公共分量和扰动分量。候选、观测和预测都使用相同分解器。Z 同时保留必要的公共状态信息和扰动信息，避免把运行状态变化误当成故障差异。

## 三、形式化定义

`S=Bφ(c(S))+Pψ(S,c(S))`，其中 `Bφ` 为公共状态分量，`Pψ` 为候选特有扰动。编码为 `E(S)=[αBφ(c),βPψ(S,c)]`。训练使用 signature 重构损失、公共状态一致性损失和 Z 空间 masked prediction loss。

## 四、可行性前提

必须存在可辨识且不含候选标签的公共状态描述；不同运行工况需足够丰富；分解应在跨拓扑和高阻场景中稳定。当前 S0 单次实验不足以证明分解可辨识，S1–S4 的元数据和多工况数据必须先完善。

## 五、与现有框架衔接

TCN、GNN 和响应特征解码器可保持不变，新增分解与重构约束。分解不能读取 candidate ID、节点 ID 或全体候选集合。若分解依赖固定节点数或固定拓扑，则不满足 S3。

## 六、论文依据与不足

拓扑识别 GNN 研究表明，显式建模拓扑不确定性有助于提升鲁棒性（[论文](https://www.frontiersin.org/journals/energy-research/articles/10.3389/fenrg.2020.613331/full)）；弱特征 GNN 研究也显示拓扑变化和弱信号是重要困难条件（[论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC12473272/)）。但这些研究通常没有证明公共/故障成分分解的可辨识性，也没有 `Oracle Top-1` 和 hardest-negative `ρ` 约束。

## 七、S1–S4 验证

S1 检查错误拓扑只影响上下文，不改变真实物理分解目标。S2 检查缺失掩码不会被分解器误当作公共零值。S3 检查公共状态描述能跨拓扑迁移。S4 检查高阻故障扰动是否被错误吸收到公共分量，并报告无故障误报和无法解释比例。

## 八、验收与回退

除 `Oracle Top-1_Z=Oracle Top-1_S`、同映射和 `ρ_Z` 条件外，还必须证明公共分量在同工况候选之间稳定、扰动分量对真实故障类型敏感。若分解降低 Oracle 排序或删除弱故障信息，立即降级为分析工具；若仅改善预测，采用 Z 中间表示、S 空间最终诊断。

## 九、判断

该路线有明确物理动机，但对数据量、运行工况和分解可辨识性要求最高。应在路线一和多工况数据稳定后再进入实现。
