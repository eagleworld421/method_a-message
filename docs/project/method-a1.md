# Method-A1：反事实稠密监督方法

## 1. 文档范围与迁移说明

本文档收束当前仓库中 Method-A1 的稳定设计和已批准规范。内容覆盖：

- 方法的研究背景、目标与整体技术框架；
- 反事实签名的形式化定义和统一监督目标；
- 数据、模型、训练、推理和评估的实现细节；
- 分项损失历史、验证集早停、损失曲线和模块运行时统计；
- S0 的稳定边界、环境依赖和可复现入口。

代码实现位于 `code/method-a1/`，采用 OpenDSS 生成 IEEE13 候选签名库，复用 Method-C 的数据生成思路与 TCN+GNN 编码器，后续签名解码、稠密监督、残差定位和检测逻辑为 A1 独立实现。首轮仅验证 S0（正确拓扑、全量观测）；S1 和 S2 留待后续实验。

当前实现行为、验证证据和下一里程碑见 `docs/project/method-a1-status.md`，不在本文档重复维护。

## 2. 研究背景与方法目标

### 2.1 背景问题

原 Method-C 的反事实语义不够严格：它主要约束同一真实故障在不同观测视图下保持一致，属于一致性或不变性学习；对于非真实候选故障位置，没有直接的物理签名监督，最终的物理验证可能退化为模型对自身输出的评价。

已有 Method-B 实验表明，直接定位模型的 Top-5 候选覆盖率约为 94.6%，候选集合不是首要瓶颈；但在 Top-5 候选中，前向模型将真实位置排在第一的比例约为 55%，主要问题是候选排序能力不足。因此 A1 将学习重点放在“每个候选假设对应什么物理签名”以及“哪个候选最能解释当前观测”上。

### 2.2 核心目标

Method-A1 的目标是构造一个条件签名预测器，使其对候选集合中的每个故障位置都给出独立的物理签名预测，并用预测签名与观测之间的残差完成反事实假设检验：

1. 对真实候选和非真实候选都提供可验证的签名监督；
2. 使故障定位从统计判别转化为候选原因的物理解释比较；
3. 在部分观测、拓扑错误和真实数据场景下，保持同一模型结构与推理方式；
4. 用上下文污染实验识别“签名被污染、残差失去区分度、系统性偏置或无故障误判”等失效模式。

## 3. 整体框架

### 3.1 端到端流程

```text
真实/仿真观测 X_O 与观测拓扑 G_obs
                │
                ▼
       上下文编码器估计运行工况 h(t)
                │
                ▼
    对候选集合 K 中每个 k 生成签名 Ŝ(k)
                │
                ├── 仿真器样本：与 ΔS_sim(k) 做稠密回归
                ├── 真实样本：真实候选回归 + 负候选排序
                └── 可选物理约束正则
                │
                ▼
       残差 r(k)=||Π_O Ŝ(k)-X_O||²
                │
                ▼
   最小残差候选作为定位结果；NO_FAULT 用于检测
```

训练阶段只读取离线生成的签名库和样本，不在每个训练步调用物理仿真器。推理阶段对候选批量前向预测；真实仿真器仅在离线签名生成和最终 Top-K 验证时调用。

### 3.2 物理生成过程

真实观测由真实拓扑、真实故障干预、运行工况和观测投影共同产生：

\[
X_O=\Pi_O\left(\Psi\left(G^*,\mathrm{do}(F=k_{true}),\varphi_f,H\right)\right)+\varepsilon
\]

其中：

- `G*` 是真实拓扑，`G_obs` 是可能含错误的观测拓扑；
- `K` 是候选故障位置集合，`k_true` 是真实位置；
- `H` 表示负荷、分布式电源出力等运行工况；
- `φ_f` 表示故障参数；
- `Π_O` 是观测投影算子；
- `Ψ` 是在候选故障干预下生成物理签名的仿真器。

### 3.3 反事实目标与定位规则

对每个候选 `k∈K` 定义：

\[
\Delta S_{sim}(k)=\Psi\left(G^*,\mathrm{do}(F=k),\varphi_f,H\right)
\]

真实候选产生现实世界签名，非真实候选产生反事实世界签名。模型学习同一映射：

\[
\hat S(k)=f_{sig}\left(G_{obs},\hat H(X_O),k\right),\quad \forall k\in K
\]

推理时计算：

\[
r(k)=\left\|\Pi_O\hat S(k)-X_O\right\|^2,\qquad
\hat k=\arg\min_{k\in K}r(k)
\]

如需融合直接定位先验，可使用：

\[
P(k\mid X_O,G_{obs})\propto P_{direct}(k\mid X_O,G_{obs})
\exp\left(-r(k)/(2\sigma^2)\right)
\]

### 3.4 已批准的重要决策

- 首轮固定为 IEEE13、S0、正确拓扑、全量观测、母线级故障候选和全候选离线签名库。
- 当前正式特征契约为标准化实部/虚部通道 `[Re_A, Im_A, Re_B, Im_B, Re_C, Im_C]`；设计稿中的极坐标描述属于历史内容。
- 复用 Method-C 的数据生成思路和 TCN 基础实现，但 A1 的候选签名解码、损失、训练、推理和评估独立维护。
- 使用普通拓扑消息传递 GNN；不引入边可信度状态、边可信度损失、MMoE 或直接定位头。
- `NO_FAULT` 使用候选索引 `N`，与母线候选 `0..N-1` 分离；嵌入冻结，有正常训练样本时使用其全局表示均值初始化，无正常样本时回退为零向量。
- OpenDSS 仅用于离线数据生成和可选物理复核，训练步骤不调用 COM；COM 不可用或求解失败时显式报错，不使用零数据兜底。
- 默认训练目标为稠密 signature MSE；ranking loss、验证集早停和模块运行时统计属于已实现的可选/辅助机制。
- 详细逐样本指标与标量汇总分离保存；当前稳定报告将逐样本残差和预测字段写入 `metrics_detail.json`，`report.json` 保留标量汇总和索引字段。

## 4. 统一监督框架

### 4.1 仿真器样本

在可执行 `do(F=k)` 的主要场景中，离线为候选集合生成 `ΔS_sim(k)`，并采用稠密绝对监督：

\[
\ell_{sim}(k)=\left\|\Pi_O\hat S(k)-\Pi_O\Delta S_{sim}(k)\right\|^2
\]

当前 S0 仅使用全枚举候选；分层候选采样、困难负样本缓存和大规模签名库内存映射属于后续设计。

### 4.2 真实样本

真实系统通常只知道实际发生的 `k_true`，无法为每个未发生候选获得绝对签名真值，因此使用两类监督：

- 真实候选回归：

  `||Π_O Ŝ(k_true) - Π_O X_O||²`。

- 反事实排序：

  `max(0, r(k_true) - r(k') + m)`，要求真实候选残差比负候选小至少一个裕度 `m`。

可选地加入电气距离衰减、拓扑连续性等物理约束正则。

### 4.3 统一训练损失

\[
\mathcal L=\mathcal L_{task}+\lambda_{sim}\mathcal L_{sim}
 +\lambda_{real}\mathcal L_{real}+\lambda_{phys}\mathcal L_{phys}
\]

同一模型、同一参数和同一推理方式服务于仿真器与真实数据；区别仅在于监督信号的密度和来源。仿真器教模型学习候选空间上的前向物理映射，真实数据教模型适应真实分布与仿真偏差。

## 5. 候选集合、无故障候选与并行设计

### 5.1 候选采样（后续设计）

推荐候选集合由以下部分组成：

- 固定包含 `k_true`；
- 约 30% 随机候选，覆盖全局；
- 约 40% 拓扑或电气距离近邻，覆盖最难区分的位置；
- 约 30% 当前模型 Top-K 中的非真实候选，作为动态困难样本。

课程式预算可从 Warm-up 阶段的 8–16 个候选，逐步增加到 Main 阶段的 24–32 个和 Hard 阶段的 32–48 个。随机候选与物理近邻可以完全离线预计算；模型混淆候选按 epoch 或固定步数周期性刷新，避免每步额外前向。

### 5.2 无故障候选

无故障不能直接编码为节点 0，以免与真实节点冲突。节点候选为 `0..N-1`，无故障索引使用 `NO_FAULT=N`；若同时包含区段候选，则将其放在节点候选之后。

当前模型构造时注册冻结零向量；训练器在存在正常训练样本时，以正常样本的全局表示均值覆盖该嵌入并保持冻结；无正常训练样本时保留零向量。该机制用于区分“无故障”和“缺失/未知”。

### 5.3 GPU 并行（后续设计）

当前实现尚未启用分层候选预算或异步困难候选刷新。未来规模化实现可采用以下流水线：

1. CPU worker 读取候选索引和离线签名目标；
2. GPU 以 `[B, |C|, N, T, F]` 的固定形状批量预测；
3. 每 `T` 步异步刷新模型混淆候选缓存；
4. 大型签名库常驻内存或使用内存映射，小型签名库可放入显存。

## 6. 当前 OpenDSS S0 实现细节

实现位于 `code/method-a1/`，依赖 Python、NumPy、PyTorch、pytest、pywin32 和本机注册的 OpenDSS COM 服务器。代码不再使用 ToyFeeder。

### 6.1 OpenDSS 数据生成

`src/data_generation/opendss_sim.py` 封装 OpenDSS 编译、潮流求解、拓扑读取和电压相量读取。首轮采用 IEEE13 馈线，候选集合为全部母线以及 `NO_FAULT`。对每个故障母线执行一次 `do(F=k)` 等价的 OpenDSS 故障干预，读取故障前后电压相量并构造动态窗口；同一工况下的所有候选签名组成离线签名库。OpenDSS 不可用或求解失败时显式抛出错误，不回退为零签名。

### 6.2 数据布局与 S0 场景

`src/data_generation/dataset_builder.py` 生成并持久化以下数组：

- `X_obs`、`X_full`：形状 `[B,N,T,6]` 的观测与完整动态波形，六个通道按 `[Re_A, Im_A, Re_B, Im_B, Re_C, Im_C]` 排列，并已使用训练集统计量做逐通道 z-score 标准化；
- `signature_bank`：形状 `[B,N+1,N,T,6]` 的全候选稠密签名；
- `mask`、`edge_mask`：S0 中分别为全一的观测与拓扑掩码；
- `edge_index`、`edge_attr`：由馈线拓扑导出的候选边及线路参数；
- `y_detect`、`y_loc`、`y_class`、`y_resist`：检测、位置、故障类别和故障阻抗标签。

标准化参数写入 `feature_scaler.npz`，包含 `mean[6]` 和 `std[6]`；`meta.json` 的 `feature_format` 为 `real_imag_standardized`。
其中 `meta.json` 的 `n_edges` 和 `directed_edge_count` 表示双向消息边数量，`undirected_edge_count` 表示物理线路数量。

每条故障样本的 `X_full` 为真实故障签名，`X_obs` 在 S0 中与之相同；正常样本的 `NO_FAULT` 签名为基准波形。数据生成与加载均支持输出目录自动创建，避免首次运行的持久化错误。

### 6.3 TCN、普通拓扑 GNN 与 A1 解码器

`src/model/temporal.py` 复用 Method-C 的因果 TCN 思路，对每个母线的 `[T,6]` 波形编码为节点表征。`src/model/gnn.py` 使用带线路属性的普通消息传递 GNN，输入 `edge_index`、`edge_attr` 和 `edge_mask`，输出节点表示 `h` 与全局表示 `g`；每条无向线路在 `edge_index` 中显式展开为正、反两个方向，模型不包含边可信度状态或边可信度损失。

`src/model/signature_predictor.py` 实现 A1 候选解码器：对母线候选读取相应节点表征，对 `NO_FAULT` 使用全局表征和冻结的正常嵌入，批量输出 `[B,C,N,T,6]`。解码器不直接读取真实候选标签，残差排序因此仍是独立的反事实比较。

### 6.4 训练、残差定位与检测

`src/trainer.py` 使用 Adam 在离线签名库上训练，默认记录签名 MSE，启用 `lambda_rank` 时对故障真实母线和正常样本 `NO_FAULT` 统一施加完整候选排序损失。训练器逐轮记录 train、val、test 分项损失，以 `val_total` 为唯一早停和最佳权重选择指标，并将最佳 epoch、实际运行轮数和早停状态保存到 checkpoint。`src/losses.py` 和 `src/eval.py` 分别实现签名损失、候选残差、Top-1/Top-K、真实排名、检测准确率、故障召回率、F1、残差间隔以及故障/正常全局最小率。`src/plotting.py` 为每种实际损失生成独立的 `loss_<name>.png`；`src/timing.py` 记录 TCN、GNN 和签名预测模块的训练前向、训练反向及推理前向时长。`main.py` 负责数据生成、训练、检查点保存、曲线输出和 `output/` 报告生成。

## 7. 验证范围与结果记录规则

首轮只验证 S0：IEEE13、正确拓扑、全量观测、全候选离线签名库。S1（拓扑错误）和 S2（部分观测）不在本轮训练或评估中，后续实验需单独设计数据划分与指标。

验证命令、最近一次验证日期、测试数量、实验配置和结果边界统一记录在 `docs/project/method-a1-status.md`。本文档只规定验收原则：纯单元测试不得依赖 OpenDSS；真实 smoke 必须记录环境、候选数、数据规模和运行耗时；单次 smoke 不得作为模型有效性的统计结论。

## 8. 评估框架与输出要求

正式 A1 评估应按拓扑错误率 `0%、2%、5%、10%` 和观测率 `30%、50%、70%、100%` 组织场景，并至少报告以下指标：

- 签名质量：全候选、真实候选和反事实候选的 MSE/MAE；
- 定位性能：Top-1、Top-K、真实候选平均排名、拓扑距离误差、残差间隔；
- 检测性能：准确率、故障召回率、正常精确率、F1、ROC-AUC、不确定率；
- 反事实验证：模型与仿真器 Top-K 一致率、仿真器修正率和解释可信度；
- 污染诊断：残差均值/标准差、真候选残差、最小与次小残差、错误候选集中度。

每个测试样本的原始记录应包含候选索引、预测签名、仿真器签名真值、残差向量、真实候选残差、无故障残差、预测位置、真实排名和上下文类型；稳定报告应通过 `metrics_detail_file` 指向详细文件。

## 10. 可复现入口

当前实现的验证命令如下（在 `code/method-a1/` 目录执行）：

```text
python -m pytest tests -q
python main.py --mode smoke --case ieee13 --samples-per-bus 1 --epochs 1
python main.py --mode evaluate --data-dir data/s0 --output-dir output/s0-eval --checkpoint-dir checkpoint/s0 --s0-only
```

运行前需确认本机已安装并注册 OpenDSS COM 组件（`OpenDSSEngine.DSS`）。数据、检查点和报告分别写入 `data/`、`checkpoint/` 和 `output/`；再次运行时会复用已完成的 checkpoint 或从已保存轮次继续训练，`evaluate` 模式可独立加载 checkpoint 评估测试集且不生成训练曲线。训练模式默认在 `output/` 生成 `loss_signature.png`、`loss_total.png`，启用排序损失后增加 `loss_ranking.png`；报告同时保存 `loss_history`、曲线路径、`fault_global_min_rate`、`normal_nofault_global_min_rate` 和 `runtime` 字段。最终交付只从 `output/` 读取。S1/S2 暂无可复现入口，避免将未验证场景误当作当前结论。
