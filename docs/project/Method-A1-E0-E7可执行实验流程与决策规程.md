# Method-A1 E0–E7 可执行实验流程与决策规程

## 一、目的、范围与证据边界

本文将 H0–H7 转化为可执行、可复核且带停止条件的实验流程，并记录 E0 的已实施协议和正式确认结果。E1–E7 仍仅规定实验设计，不预先选择因素分解、不变表示、度量学习或其他具体表示学习方法。

截至本文形成时，可以作为既有证据使用的结论仅包括：

- 已验证但仅限当前 IEEE13、S0、全量观测和既有数据版本：真实物理响应的 Oracle fault Top-1 为 1.0，且当前模型与 Oracle 上界之间存在明显差距；
- 已验证但仅限既有 Z 路线一配置及扫描范围：现有路线一未改善核心 `rho`，高 `R` 可由 identity、random 或 label-shuffle 对照产生；
- 初步验证：S1–S4 Oracle 派生视图和物理邻近性分析流程可运行；
- 已验证但仅限 E0 当前理想 OpenDSS、IEEE13、全节点三相复电压、无分布式电源和已覆盖常规阻抗：故障检测信息与母线排序信息高于各自零假设；全局唯一母线距离分离未通过。
- 未验证：真实传感器噪声下的信息充分性，S2 与 S4 的正式结论，S3 跨拓扑泛化，因素来源及可辨识性，独立距离结构瓶颈，可靠物理约束，唯一母线操作阈值及独立数据外推。

因此，本文不把 S0 结果外推至 S2 或 S4，不把 Oracle 可分等同于诊断几何瓶颈，也不把单拓扑物理邻近性趋势写成训练约束依据。

## 二、统一实验对象与冻结协议

### 2.1 变量角色

- 故障变量 `F`：故障位置、故障类型与故障阻抗；
- 条件变量 `C`：负荷、分布式电源出力、运行点及决定真实响应的真实拓扑 `G*`；
- 观测变量 `O`：观测节点、时间点、通道、观测掩码及观测覆盖率；
- 无关干扰候选 `N`：测量噪声、数值误差、与诊断目标无关的背景扰动，以及在特定任务中不应决定故障判断的台账误差；
- 观测拓扑 `G_obs`：S1 中模型实际获得的拓扑上下文，不得与 `G*` 合并；
- 交互项：至少包括 `F×C`、`F×O`、`F×G*`、阻抗×观测条件和 S4×S1/S2/S3。

上述分类必须由 E1、E2 的结果复核。某一非故障变量只有在其对故障表现无实质作用且抑制后不损失故障信息时，才可归入应抑制干扰；会改变故障表现的变量应保留为条件变量或显式交互变量。

### 2.2 独立统计单位与配对单元

一个物理实验单元定义为：

```text
topology_family / topology_id / operating_condition_id /
fault_type / fault_location / fault_impedance / physical_replicate_id
```

同一物理单元派生的噪声重复、观测掩码、错误拓扑视图、固定变换和模型输出均为相关观测，不得作为独立样本计数。统计推断优先使用保持配对的层级 bootstrap 或块内置换；跨拓扑结论以拓扑实例为统计单位。

### 2.3 正式实验前必须冻结的文件

正式 E0 前必须形成并冻结以下协议文件；其阈值可以由独立 pilot 确定，但不得使用正式测试集反向选择：

- `protocol.json`：变量角色、候选集合、距离定义、指标版本、显著性控制方法和停止规则；
- `data_manifest.json`：数据版本、仿真器版本、馈线、通道语义、单位、标准化统计量、文件校验值和生成配置；
- `split_manifest.json`：训练、验证、测试及独立复核集合的组标识；
- `seed_manifest.json`：物理生成、噪声、掩码、训练、bootstrap 和置换检验的独立随机种子；
- `decision_thresholds.json`：已固定阈值、待 pilot 确定项、pilot 数据来源及冻结时间；
- `metric_spec.json`：`delta`、`e`、`rho=e/(delta+epsilon)`、错序、检测、校准、拒识及 Oracle fidelity 的精确定义。

### 2.4 统一防泄漏规则

- 先按 `topology_family`、`topology_id` 和 `operating_condition_group` 划分，再生成或分配派生视图；同一 `base_sample_id` 的所有派生视图必须处于同一集合；
- 同一工况下的 NO_FAULT、全部故障候选、不同阻抗档和物理重复必须作为一个配对块整体划分；
- 标准化、白化、差分参考、阈值、校准器、拒识规则、困难候选选择规则及方法超参数只能由训练集和验证集确定；
- 测试拓扑、测试工况、测试掩码、独立数据及真实数据不得参与表示、约束、阈值或超参数选择；
- E5 的关系发现集合与关系确认集合必须按拓扑互斥；只有确认集合通过的关系才可用于后续训练约束；
- E7 独立数据在方法、阈值和拒识规则冻结后只允许评估一次。若依据该结果修改方法，原集合降级为开发集，必须另设新的独立测试集。

### 2.5 统一统计规则

- 主要效应报告 95% 置信区间、配对效应量和原始样本数、独立块数及拓扑数；
- 连续配对指标以块内配对置换检验和层级 bootstrap 为主；二元成对结果使用配对比例差及 McNemar 或块内置换；排序与曲线指标使用层级 bootstrap；
- 少量预注册主假设使用 Holm 校正；探索性分层使用 Benjamini–Hochberg 控制假发现率，并明确标记为探索性；
- bootstrap 次数、置换次数、正式样本量和训练随机种子数均“待 pilot 确定”。确定依据分别为 Monte Carlo 标准误、目标置信区间宽度、最小关注效应的功效分析和跨种子方差；
- 训练型实验的 pilot 至少包含三个诊断性随机种子；正式重复数由 pilot 方差决定，三个种子本身不构成正式充分性保证；
- 每个实验均允许三种门结论：`通过`、`未通过`、`证据不足`。置信区间跨越零假设或实用性阈值、关键分层缺样本、分组无效或独立复核缺失时，必须判为证据不足，不得按点估计强行归类。

## 三、带条件分支的完整执行流程

1. 冻结第 2 节协议并完成数据契约校验；失败时停止全部正式实验。
2. 执行 E0。若目标观测条件下信息不足，转向增加观测、调整候选粒度或输出候选集合；若信息存在但被噪声覆盖，转向观测设计、去噪及不确定性；两种情况均不进入诊断几何学习。
3. E0 在明确适用范围内通过后，先执行 E0-COV 模板覆盖补充消融，再执行 E1。只有覆盖控制后仍存在跨工况排序变化，才计为 H1 的工况证据；若变化由阻抗或工况模板覆盖解释，优先修正签名库，不启动因素表示路线。
4. 若 E1 表明工况或 `F×C` 交互会实质改变真实响应及候选排序，执行 E2，区分无关干扰、条件变量和故障—工况交互，并审计显式因素识别所需的可辨识条件。
5. 只有 E1 证明因素影响不可忽略，且 E2 表明存在可比较的方法分支时，才启用 E3；否则记录跳过原因。
6. 执行 E4-A：依次比较原始空间、predictor-only、标准化、白化、固定差分和决策校准。若简单方案已经解释主要改善，停止学习型诊断空间设计。
7. 只有 E4-A 排除信息、噪声、预测器、校准及固定变换足以解释失败，并给出剩余距离结构证据后，才允许另行确认一个低容量、冻结预测器的诊断几何探针并执行 E4-B。本文不指定该探针的具体表示方法。
8. 只有 E4-B 在独立测试、多随机种子和零假设对照下确认独立距离结构瓶颈，才进入正式学习型诊断空间的方法设计。
9. E5 独立验证候选物理关系。每条关系分别判定；未通过独立拓扑确认的关系不得写入训练损失或强制验收门。
10. 执行 E6。S2 与 S4 必须分别完成 Oracle 信息层、跨掩码或跨阻抗稳定性、端到端模型层和组合交互层验证；不得以 S0 或单一 smoke 替代。
11. 方法、物理约束和场景配置冻结后执行 E7，使用验证集确定阈值、校准与拒识规则，再在独立数据上一次性评估。
12. 最终只保留通过相应决策门的最小方法能力；任何未通过或证据不足命题均不得转化为模型模块或论文结论。

## 四、E0：Oracle 信息充分性与噪声边界实验

### 4.0 已冻结边界与正式运行状态

- 目标环境为理想 OpenDSS 仿真、IEEE13、无分布式电源、全节点传感器；负荷逐负荷在基准值的 `0.8–1.2` 倍范围变化，同一负荷的有功和无功使用同一倍率以保持功率因数。
- 诊断输入仅为同一事件窗口内、由故障前片段建立基准的全节点三相复电压响应；诊断不得读取负荷倍率、故障类型、故障相别、故障阻抗或真实故障发生时刻。
- 任务包含正常/故障检测和全部物理可行母线的排序，不输出故障类型或阻抗；故障类型覆盖 `LG`、`LL`、`LLG`、`LLL`、`LLLG`。
- pilot 已冻结：2 个签名库负荷工况，7 个模板阻抗，4 个互斥评价阻抗，2 次 OpenDSS 数值重复，2 次人为动态窗口重复，故障延迟候选 `0/2/4` 步，正式确认工况 8 个，块级 bootstrap 400 次。
- 正式运行 `e0-confirm-20260915-seed342` 包含 5672 个模板、21640 条观测和 5410 个纯净物理参考；仿真调用 12713 次且全部收敛。
- H0 在“存在可用于检测和 Top-K 母线排序的信息”这一限定意义下通过；全局唯一母线距离分离未通过。因此当前只允许输出 Top-K 和风险—覆盖率曲线，唯一母线阈值仍须由应用错误代价人工选择并在后续独立数据上验证。
- 当前人为相移、故障前幅值摆动和阻尼振荡只属于未按传感器规格标定的敏感性扰动，不得写成真实测量噪声结论。

### 4.1 命题、可验证内容与边界

- 对应命题：H0；E6-S2.1/S2.2 和 E6-S4.1/S4.2 是 H0 在 S2、S4 条件下的专门复验。
- 能够验证：在固定 `F、C、O、G*` 和候选集合时，真实响应是否包含高于测量、数值和重复生成误差的定位与检测信息，以及不可分候选对的适用范围。
- 不能验证：预测器是否有效、表示几何是否为瓶颈、模型是否跨拓扑泛化，或某种表示学习方法是否必要。

### 4.2 前置条件与进入门

- 第 2 节协议、候选粒度、目标观测条件、噪声来源和重复仿真定义已经冻结；
- signature library 校验值、`G*`、`O`、工况和物理重复标识完整；
- 若重复仿真仍复用同一随机波形扰动而不形成独立重复，则只可运行工程 pilot，不得形成噪声边界结论。

### 4.3 数据、来源与新增需求

- 可复用：既有 IEEE13 S0 全候选 `signature_bank`、NO_FAULT 候选、S0 Oracle 报告和逐候选 residual 逻辑；
- 必须新增：对同一物理单元的独立求解重复、独立动态窗口重复和目标测量噪声重复；保存未标准化物理量、噪声注入前后观测、求解状态及随机源；
- 每个故障单元必须有同工况 NO_FAULT 对照；S2、S4 数据不在 E0 中由 S0 代替，而在 E6 中按相同规程复验。

### 4.4 变量与交互项

- 自变量：故障位置、类型、阻抗、工况、观测条件、噪声来源与强度、物理重复；
- 因变量：Oracle Top-1/Top-K、真实候选排名、候选错序率、`delta`、故障—NO_FAULT gap、并列率及 gap-to-noise ratio；
- 控制变量：候选集合、距离定义、标准化统计量、拓扑、时间窗和仿真器版本；
- 交互项：故障类型×阻抗、故障×工况、阻抗×噪声、观测率×噪声及拓扑×故障。

### 4.5 生成与配对

- 对每个 `F×C×G*` 单元生成无噪声参考、独立数值重复、独立动态窗口重复和各目标噪声重复；
- 同一重复内对全部候选使用一致的工况、物理参数和噪声语义，避免候选特有的随机扰动被误认为候选差异；
- `delta` 使用真实候选与全候选 hardest negative 的 residual 差；噪声边界使用同一物理状态重复之间造成的 residual 差与排序扰动分布估计；
- gap-to-noise ratio 的分母定义及噪声分位点“待 pilot 确定”，由重复误差分布稳定性和预期误报风险确定。

### 4.6 划分与防泄漏

- E0 不训练预测器，但噪声模型、分位点和判据仍使用校准组确定，在互斥确认组上报告；
- 同一工况、拓扑和故障单元的所有重复必须整体进入同一组；
- S2 掩码和 S4 阻抗范围不得依据 E0-S0 测试结果选择。

### 4.7 基线、消融与零假设

- 基线：无噪声 clean Oracle；
- 消融：仅数值重复、仅动态窗口重复、仅测量噪声及其组合；
- 零假设：候选标签置换、候选 residual 置换、同状态重复对照、NO_FAULT 噪声对照及复制候选造成的人工并列对照。

### 4.8 指标与统计

- 主指标：分层 Oracle Top-1、候选错序率、`delta` 低分位数、gap-to-noise ratio 和不可分比例；
- 次指标：Top-K、真实排名、fault-to-fault gap、fault-to-NO_FAULT gap 及 hardest-negative 身份稳定性；
- 采用物理单元层级 bootstrap 95% 区间，块内置换检验 clean 与噪声条件差异；多故障类型与多观测条件使用 Holm 校正；
- 重复次数和正式样本量待 pilot 依据噪声分位数区间宽度与最小关注不可分比例确定。

### 4.9 通过、未通过与证据不足

- H0 信息充分性通过：数值重复确认集的故障召回率和正常特异度区间下界均高于 `0.5`，且纯净与数值重复确认集的 Top-1 区间下界均高于随机母线零假设 `1/16`；该结论只表示检测与排序信息存在。
- H0 信息充分性未通过：检测或定位主指标的区间上界不高于相应零假设。
- H0 信息充分性证据不足：区间跨越零假设、数值重复不足、独立正常工况不足、关键故障类型缺失或分组语义无法分离。
- 全局唯一母线距离分离单独判定：数值重复下故障 gap-to-noise 中位数区间下界高于 `1` 方可通过，上界不高于 `1` 判为未通过，其余为证据不足。该判定不改变 H0 的信息存在结论，也不等同于诊断几何瓶颈。
- 即使全局唯一分离通过，唯一母线输出门仍必须使用不读取真实标签的预测置信分数，在校准集上依据人工给定错误代价冻结，并在独立数据上验证。

### 4.10 输出

- 文件：`protocol.json`、`config.json`、`data_manifest.json`、`split_manifest.json`、`seed_manifest.json`、`decision_thresholds.json`、`metric_spec.json`、`sample_metrics.jsonl`、`candidate_pair_metrics.jsonl`、`noise_replicates.jsonl`、`risk_coverage.jsonl`、`summary.json`、`decision.json`、`report.md` 和 `plots/`；
- 关键字段：全部物理单元标识、噪声来源/重复号、真实与 hardest-negative 候选、residual 向量、检测间隔、真实母线定位间隔、预测前两名间隔、可部署唯一输出置信分数、噪声边界、Top-K 和证据状态；
- 图形：gap 与噪声边界分布、风险—覆盖率曲线、按故障类型的 Top-1 和母线混淆矩阵；
- 报告必须分别标记已验证、初步验证和未验证范围。

### 4.11 结果分支

- 信息不足：增加传感、时间或可控激励，合并候选粒度，或输出候选集合；停止表示几何路线。
- 信息存在但全局唯一分离失败：保留 Top-K，使用风险—覆盖率设计选择性唯一输出；不得把该结果直接解释为距离结构瓶颈。
- 仅部分分层通过：后续实验只在通过范围内进行，失败分层单独走信息/噪声分支。
- 全部关键分层通过：进入 E1。

### 4.12 代码复用与最小新增

- 可复用：`src/signature_library.py`、`src/oracle.py`、`scripts/diagnose_oracle_separability.py`、`scripts/run_oracle_suite.py` 及 Oracle 图形模块。
- 最小新增：可重复控制的物理/波形/测量噪声生成接口；噪声重复数据契约；gap-to-noise 统计与块级置信区间；协议和决策文件写出器。现有 `build_dynamic_window` 的候选相关随机扰动必须先被明确分离或统一控制。

### 4.13 E0-COV：模板覆盖归因消融

E0-COV 是 E0 的补充归因实验，不替代 E0 正式结果，也不属于 H1。其目的仅是判断当前 Top-1 未达到稳定唯一定位，究竟有多少可由模板阻抗和模板工况覆盖不足解释。

#### 4.13.1 实验臂与配对原则

- `C0 当前覆盖`：保持正式 E0 的 2 个模板工况和 7 个模板阻抗，作为逐样本配对基线；
- `CR 阻抗匹配`：在保持模板工况不变时，将评价阻抗加入模板集合；
- `CC 工况匹配`：在保持原模板阻抗不变时，为确认工况生成模板；
- `CRC 阻抗与工况匹配`：同时匹配评价阻抗和确认工况，作为 nuisance-aware 诊断上界；
- `CD 覆盖密度曲线`：仅利用开发/校准工况逐步增加阻抗网格密度和模板工况数，评价非测试特定的连续覆盖收益。

每个实验臂必须评价完全相同的确认物理单元，并保持候选母线、故障类型、相别、发生延迟、观测窗口和距离定义不变。`CR/CC/CRC` 的新增模板必须由独立生成记录构造，禁止直接复制评价观测；其中 `CRC` 在确定性 OpenDSS 下可能形成近似精确查表，因此只解释为覆盖上界，不得作为可部署结果。`CD` 的密度、网格和工况选择只能由开发/校准数据确定。

#### 4.13.2 指标、对照与统计

- 主指标为逐物理单元的 Top-1 变化、真实母线 rank 变化、定位 gap 变化和由错排恢复为正确的比例；Top-3、Top-5、hardest-negative 身份和检测结果作为辅助指标；
- 同时报告按母线宏平均指标，避免三相母线具有更多故障相别组合而主导总体结果；
- 零假设包括等规模重复模板、候选标签置换模板和保持模板数量但不增加阻抗/工况覆盖的随机扩容；由此区分覆盖语义收益与单纯增加模板数量的收益；
- 使用物理单元配对 bootstrap 和块内置换检验比较 `C0→CR`、`C0→CC`、`C0→CRC`，并报告 `CR/CC` 的联合结果是否超出任一单独补齐；不假设阻抗和工况效应线性可加；
- 实际重要性阈值、覆盖密度停止点和正式样本量均待 pilot 依据配对改善区间、曲线平台位置和计算成本确定。

#### 4.13.3 判据、输出与后续分支

- 若 `CR` 产生稳定且实际重要的主要恢复，而 `CC` 增益有限，则优先研究连续阻抗覆盖、插值或模板检索，不据此进入工况因素方法；
- 若 `CC` 在 `CR` 控制后仍产生稳定恢复，则工况是候选排序的重要条件变量候选，进入 E1 和 E2；
- 若只有 `CRC` 显著恢复，则记录阻抗—工况交互，不允许把两者分别解释；
- 若 `CRC` 后 Top-1 仍明显不足，则模板覆盖不能解释主要错排，进入 E1-C 与 E4-A 检查候选本征重叠和距离规则；
- 若改善区间跨越 pilot 冻结的实际重要性界，结论为证据不足，补充覆盖密度或独立工况，不选择表示方法。

输出新增 `coverage_arm_manifest.json`、`coverage_pair_metrics.jsonl`、`coverage_summary.json`、`coverage_decision.json`、覆盖密度曲线、逐母线恢复图和 matched/unmatched 排名迁移图。所有结论必须标记“覆盖归因”，不得写成故障因素或诊断几何结论。

## 五、E1：配对因素来源实验

### 5.1 命题、可验证内容与边界

- 对应命题：H1。
- 能够验证：在控制模板覆盖后，负荷工况变化是否仍实质改变真实物理响应、候选 residual 顺序、真实母线 rank 和 hardest-negative；故障变化与工况变化的相对量级及交互；错排是否集中于稳定的局部候选集合。
- 不能验证：任何因素已被唯一恢复；工况一定应被删除；局部混淆一定具有可用于训练的物理约束；或应选择残差化、条件化、度量学习及其他具体表示方法。
- E1 只分析真实响应与固定 Oracle 规则，不训练预测器。E0 已确认的故障检测结果作为守恒指标，E1 主问题是母线排序而非重新优化正常/故障检测。

### 5.2 前置条件与进入门

- E0 在当前理想 IEEE13、全节点观测和常规阻抗范围内已确认存在检测与 Top-K 定位信息；E1 不外推至 S2、S4、真实噪声或跨拓扑；
- E0-COV 至少完成 `C0/CR/CC/CRC` 四臂，使工况引起的排序变化能够与模板覆盖不足区分；
- 每个故障状态必须在多个互斥负荷工况下重复生成，且故障母线、类型、相别、阻抗、拓扑、观测和窗口延迟可严格固定；
- 当前事件对齐人为波形扰动会在正常样本中制造伪瞬态，不进入 E1 主归因。E1 主分析使用纯净与 OpenDSS 数值重复；真实噪声留待重新定义后评价；
- 若某因素与故障始终共同变化，或无法形成跨工况交叉块，只允许报告混杂并补充数据，不进入方法分支。

### 5.3 数据、来源与新增需求

- 可复用：E0 的物理可行故障枚举、负荷倍率生成、互斥 library/calibration/confirmation 工况、逐候选 residual、真实 rank、hardest-negative、母线清单和数值重复；
- 必须新增：同一 `F=(k,t,p,R_f)` 在多个负荷向量 `C` 下的完整交叉响应；同一工况下的多个故障状态；与各工况严格配对的 NO_FAULT；E0-COV 各模板臂的评分结果；
- 工况元数据必须保存每个负荷的有功、无功、共同倍率和基准值。当前不包含分布式电源，禁止把未变化的 DG 写成已验证因素；
- 负荷仍按 `0.8–1.2` 范围独立变化，同一负荷的有功和无功使用相同倍率以保持功率因数。负荷参数只用于生成、配对和分层，不进入诊断器；
- 工况数、故障状态配额和交叉块数量待 pilot 依据排序翻转率区间宽度、母线宏平均稳定性和运行成本确定。

### 5.4 变量与交互项

- 自变量：负荷工况 `C`、故障状态 `F=(k,t,p,R_f)`、模板覆盖臂、配对类型及 OpenDSS 数值重复；
- 因变量：物理响应距离 `D_C/D_F`、候选 residual 向量、真实母线 rank、Top-1 翻转、Top-K 保持、hardest-negative 身份、候选序相关、错排目标和局部性；
- 控制变量：拓扑、全节点观测、时间窗、距离定义、故障位置/类型/相别/阻抗或工况中未被当前配对改变的部分；
- 主交互项：`F×C` 和阻抗×工况；模板覆盖臂×工况用于判断观察到的工况效应是否只是签名库覆盖伪影；
- 当前 E1 不改变观测视图、真实拓扑或传感器噪声，因此不估计 `F×O`、`C×O` 或跨拓扑交互；这些交互留在 E6。

### 5.5 生成与配对

- `E1-A 跨工况排序稳定性`：固定 `F=(k,t,p,R_f)`、拓扑、观测和窗口延迟，比较 `S(F,C_1)` 与 `S(F,C_2)`；在 `C0` 与覆盖控制臂上分别计算真实 rank 变化、Top-1 翻转、候选排序相关、Top-K 集合变化和 hardest-negative 转移；
- `E1-B 故障—工况配对比较`：构造 `S(F_1,C_1)`、`S(F_1,C_2)`、`S(F_2,C_1)`、`S(F_2,C_2)` 的 `2×2` 交叉块，分别形成同故障异工况距离 `D_C`、异故障同工况距离 `D_F` 及联合变化。`R_mix` 和交互对比只作描述性、预测性归因，不假设 `S(F,C)` 对故障与工况线性可加；
- `E1-C 错排结构与局部性`：对每个真实母线 `i` 统计被候选 `j` 超过的条件概率 `P(j|i)`、hardest-negative 转移矩阵和跨工况稳定性；关联拓扑跳数、电气距离和结构距离，仅判断错排是否局部集中，不形成训练约束；
- 对 NO_FAULT 仅构造跨工况配对，检查工况变化是否破坏 E0 检测结论；该结果是守恒检查，不与故障母线 rank 混合；
- 每个配对在当前覆盖 `C0` 和至少一个覆盖控制臂下重复评分。若排序翻转只在 `C0` 出现而在覆盖控制后消失，归因于模板覆盖，不计为 H1 的工况效应。

### 5.6 划分与防泄漏

- 先按负荷工况块划分开发、校准和确认集合，再在各集合内部形成故障交叉块；同一负荷向量、物理故障状态、数值重复及全部模板覆盖评分不得跨集合；
- E1-A 的确认工况不得参与覆盖密度、实际重要性阈值、困难候选规则或距离标准化的选择；
- `CC/CRC` 是明确标记的诊断上界臂，其确认工况模板不得流入 `C0/CD` 的可部署覆盖结论；
- 形成配对时不得跨集合寻找匹配样本；由同一物理状态组合出的多个工况对不得被视为相互独立；
- 任何柔性贡献模型只允许在开发组拟合并在确认组评价，且不能取代配对距离和排序翻转的主分析。

### 5.7 基线、消融与零假设

- 噪声基线：同一 `F×C` 的 OpenDSS 数值重复距离；
- 工况基线：同故障异工况；故障基线：异故障同工况；NO_FAULT 基线：正常状态跨工况距离；
- 覆盖消融：`C0` 与 `CR/CC/CRC/CD` 的同一物理单元评分，区分工况物理效应和模板覆盖效应；
- 排序零假设：工况标签块内置换、候选标签置换、保持母线先验的随机排序和多数类母线基线；
- 配对零假设：保持边际分布但破坏 `F×C` 对应关系的随机匹配，以及复制同状态响应形成的零变化对照；
- 局部性零假设：在保持每个真实母线错误次数和候选频率的条件下置换错误目标，检验观察到的拓扑/电气邻近集中是否超过候选先验。

### 5.8 指标与统计

- E1-A 主指标：真实母线平均/中位 rank 位移、Top-1 保持与翻转率、Top-3/Top-5 保持率、候选 residual 排序的 Kendall 相关、Top-K Jaccard、hardest-negative 一致率及其转移矩阵；
- E1-B 主指标：`D_C`、`D_F`、`R_mix=D_C/(D_F+epsilon)` 的分布，以及 `2×2` 块内联合变化相对单因素变化的偏离；不把该偏离解释为可加交互系数；
- E1-C 主指标：`P(j|i)`、逐母线错排熵、错误目标集中度、错误候选的拓扑跳数/电气距离分布和局部错误比例；
- 所有 Top-K 与翻转结果同时报告样本加权和逐母线宏平均值；检测单列故障召回率与正常特异度，防止类别不均衡掩盖误报；
- 以负荷工况和物理故障状态为双层块进行 bootstrap；工况对的组合数量不计作独立样本。块内置换用于排序翻转、覆盖臂差异和局部性零假设；预注册主比较使用 Holm 校正；
- 实际重要性阈值、正式工况数、配对数量、宏平均稳定性界和局部集中界均待 pilot 根据数值重复基线、效应区间宽度及最小关注 rank 退化确定。

### 5.9 通过、未通过与证据不足

- `H1-工况通过`：覆盖控制后，跨工况 rank 位移、Top-1 翻转或候选邻域变化仍超过 pilot 冻结的实际重要性界，95% 区间排除零假设，并在互斥确认工况复现；
- `H1-工况未通过`：覆盖控制后的全部预注册工况效应落在可忽略区间内，故障效应 `D_F` 仍稳定高于数值重复基线；
- `覆盖归因`：工况相关错排在 `C0` 显著，但在 `CR/CC/CRC` 中消失或降入可忽略区间；此时不得判定工况破坏真实响应几何；
- `交互通过`：单独补齐阻抗或工况均不能解释结果，而联合覆盖或 `2×2` 块显示稳定的非单因素行为；只记录阻抗—工况交互，进入 E2，不宣称可加分解；
- `局部错排成立`：错误目标相对受限置换零假设显著集中于稳定候选集合，并在确认工况复现；该结论只指导后续困难候选审计，未经 E5 不得形成物理约束；
- `证据不足`：交叉覆盖不足、工况与故障共变、独立工况过少、母线宏平均区间过宽、覆盖臂污染或结果只在单一工况出现。

### 5.10 输出

- 文件：公共协议文件、`condition_manifest.json`、`pair_manifest.jsonl`、`pair_metrics.jsonl`、`ranking_transition.jsonl`、`confusion_locality.jsonl`、`effect_summary.json`、`decision.json`、`report.md` 和 `plots/`；
- 关键字段：pair/block ID、模板覆盖臂、固定和改变因素、两侧工况与故障标识、响应距离、完整候选 residual/rank、Top-K、hardest-negative、翻转方向、母线宏平均权重、拓扑/电气距离及交互标识；
- 图形：跨工况 rank 迁移图、Top-1 翻转森林图、覆盖臂恢复曲线、`D_C/D_F/R_mix` 分布、hardest-negative 转移矩阵、`P(j|i)` 混淆图和错误候选物理距离分布；
- 报告必须将“模板覆盖效应”“工况物理效应”“阻抗—工况交互”和“局部错排结构”分别下结论，不得合并为笼统的背景干扰。

### 5.11 结果分支

- 主要由阻抗覆盖解释：优先模板网格、连续插值或检索设计；不启动背景残差化或条件不变表示；
- 主要由工况覆盖解释但真实跨工况响应变化可忽略：优先模板覆盖和条件检索；不把工况定义为应删除干扰；
- 覆盖控制后工况仍显著改变排序：进入 E2，区分工况是必须保留的条件变量、可抑制无关成分，还是 `F×C` 交互；仅此分支允许把受限残差化/条件化表示列为后续候选；
- 工况影响可忽略：跳过 E2/E3 的因素路线，直接进入 E4-A 的 predictor-only、标准化、白化、固定差分和 calibration-only 对照；
- `CRC` 后仍存在严重错排：进入 E4-A 检查距离规则和候选本征重叠；若错误局部集中，只记录 hardest local negatives，不立即使用 triplet/contrastive 强制拉开；
- 局部性与物理邻近稳定相关：将该关系送入 E5 独立复核；E5 通过前不得进入训练损失；
- 共变或覆盖无法拆分：补充交叉工况和覆盖臂，结论保持证据不足，不进入方法选择。

### 5.12 代码复用与最小新增

- 可复用：E0 数据生成器、物理故障枚举、load condition manifest、未知因素签名族 residual、逐样本 Top-K/rank、候选对文件、数值重复边界，以及既有拓扑/电气距离计算。
- 最小新增：E0-COV 模板臂构造与等规模对照；完整 `F×C` 交叉工况生成；无泄漏配对清单；rank/Top-K/hardest-negative 转移；逐母线宏平均；双层块 bootstrap；受限混淆置换和局部性分析。
- E1 不新增预测模型、表示网络或训练损失；任何残差化、条件化或困难负样本方法只在 E1/E2/E4 的进入门满足后另行设计。

## 六、E2：故障与工况干预对照实验

### 6.1 命题、可验证内容与边界

- 对应命题：H2。
- 能够验证：现有交叉干预是否提供区分故障变化、工况变化及其交互的必要数据条件；故障方向能否在留出工况上稳定复现。
- 不能验证：潜变量唯一对应真实因素，或高探针准确率等同于因果可辨识。

### 6.2 前置条件与进入门

- E1 表明非故障因素影响不可忽略；
- 每个选定工况均存在同工况 NO_FAULT 与多个故障干预，每个选定故障均跨多个工况重复；
- 推理阶段工况是否可观测、测量精度和可用时点已经说明。

### 6.3 数据、来源与新增需求

- 可复用：同一 signature bank 内同工况 NO_FAULT 候选与故障候选；
- 必须新增：平衡的 `F×C` 交叉设计、留出工况、实际工况向量、工况测量可用性标识及同条件物理重复；
- 对工况不可观测的目标场景，必须额外构造工况隐匿评估视图，不能在方法输入中泄漏真实工况。

### 6.4 变量与交互项

- 自变量：故障干预、工况干预、工况可见性、拓扑和观测条件；
- 因变量：`Delta_F=S(F,C)-S(NO_FAULT,C)` 的跨工况方向稳定性、`Delta_C`、子空间重叠、留出工况故障探针、条件工况探针和交互对比；
- 控制变量：故障类型、位置、阻抗、拓扑、观测和噪声；
- 交互项使用经验对比 `I_FC=[S(F,C2)-S(NO,C2)]-[S(F,C1)-S(NO,C1)]`，该定义不假设响应线性可加。

### 6.5 生成与配对

- 每个工况先生成 NO_FAULT，再在相同条件下生成全部目标故障；
- 对同一故障在多个工况中重复生成，构造 `Delta_F`；NO_FAULT 工况对构造 `Delta_C`；
- 留出完整工况块检验方向与探针迁移，不能随机留出同一工况的派生样本。

### 6.6 划分与防泄漏

- 训练、验证、测试按工况组互斥；跨拓扑复核时再按拓扑组互斥；
- 子空间、探针和任何标准化仅由训练组拟合；验证组选择维数或正则；测试组只评估；
- NO_FAULT 与相同工况下全部故障保持同组。

### 6.7 基线、消融与零假设

- 基线：原始响应、只给故障标签的探针、只给工况标签的探针；
- 消融：工况可见/不可见、去除交互对比、只用单工况和只用单故障类型；
- 零假设：块内故障标签置换、工况标签置换、随机正交子空间、破坏 `F×C` 配对和只保留样本编号的伪探针。

### 6.8 指标与统计

- 主指标：跨工况方向一致性、故障/工况子空间主角或重叠度、留出工况故障探针相对置换基线的增益、`I_FC` 效应；
- 次指标：控制故障后的工况可预测性、控制工况后的故障可预测性及按故障类型的稳定性；
- 使用工况块 bootstrap、块内置换和跨拓扑复核；探针只使用预注册低容量族并匹配容量；
- 子空间维数、探针容量和实际稳定性阈值待 pilot 确定，依据训练组谱稳定性和留出工况区间，而非测试准确率。

### 6.9 通过、未通过与证据不足

- 通过：交叉干预覆盖充分，故障信号在留出工况上稳定高于标签置换基线，且故障、工况和交互可形成可复核的部分区分；该结论仅表示具备方法比较条件，不表示唯一分解。
- 未通过：故障与工况始终共变，或留出工况的故障信息回到置换水平且无法由可观测条件解释。
- 证据不足：交叉单元稀疏、工况标签不完整、子空间结果对维数选择不稳定或缺少独立工况复核。

### 6.10 输出

- 文件：`intervention_manifest.jsonl`、`contrast_metrics.jsonl`、`probe_predictions.jsonl`、`subspace_summary.json`、`decision.json`、`report.md` 和 `plots/`；
- 关键字段：干预前后单元、`Delta_F`、`Delta_C`、`I_FC`、工况可见性、探针折、真实/置换标签、留出工况和效应状态；
- 图形：方向一致性分布、子空间主角森林图、留出工况探针曲线和交互对比图。

### 6.11 结果分支

- 影响显著且部分可辨识、并要求解释性：允许 E3 纳入显式因素思想；
- 无法唯一分解但跨工况故障关系稳定：E3 优先比较条件或环境鲁棒思想；
- 只有部分因素可识别：E3 比较部分显式与条件化组合；
- 无交叉识别基础：补数据，E3 不启用。

### 6.12 代码复用与最小新增

- 可复用：同事件全候选 signature、NO_FAULT 候选、现有模型输入和 Z 对照输出框架。
- 最小新增：平衡交叉干预生成器、工况向量与可见性契约、干预对比分析、留出工况分组器和受控探针评估。不得复用当前随机 train/test 划分作为 H2 证据。

## 七、E3：统一协议下的方法思想对照实验

### 7.1 命题、可验证内容与边界

- 对应命题：H3。
- 能够验证：在相同数据、预测器、预算和评价协议下，显式因素识别、条件/环境鲁棒表示及二者组合的思想级相对适用性。
- 不能验证：某一思想恢复了唯一真实因素，或在未覆盖 S1–S4 与独立数据时具有一般有效性。

### 7.2 前置条件与进入门

- E1 已确认非故障因素达到实际重要性阈值；
- E2 已确认至少存在一个有数据依据的方法分支；
- E3 仅比较 E2 允许的思想族。E2 不支持显式识别时，不得把显式路线加入后再据失败宣称其理论无效。

### 7.3 数据、来源与新增需求

- 使用 E1/E2 的交叉数据和完全相同的分组清单；
- 必须覆盖留出工况，并保留正常样本、噪声视图和故障—工况交互；
- 若条件路线需要推理时工况输入，只能使用目标系统实际可获得的测量量。

### 7.4 变量与交互项

- 自变量：方法思想族、工况可见性、环境、故障类型和阻抗；
- 因变量：跨工况诊断、故障信息保持、残余无关干扰可预测性、交互保真、校准和稳定性；
- 控制变量：预测器初始化、参数/时间预算、数据划分、早停、候选集合、距离和阈值选择流程；
- 交互项：思想族×工况可见性、思想族×故障类型、思想族×环境。

### 7.5 生成与配对

- 所有思想族读取同一基础样本和同一派生视图；每个训练种子形成成对比较；
- 比较对象只定义能力接口，不在本文预选具体算法：不做因素处理、显式来源接口、条件/环境鲁棒接口、部分显式加条件接口；
- 每个接口的最小候选实现需在 E3 启用前另行确认，并接受相同预算约束。

### 7.6 划分与防泄漏

- 采用 E2 的留出工况与拓扑分组；同一 `base_sample_id` 跨方法共享但不跨集合；
- 方法选择使用验证组；测试组不得选择思想族、损失权重或工况输入；
- 残余工况探针在冻结表示上训练，并使用独立折，避免用训练探针评价训练表示。

### 7.7 基线、消融与零假设

- 前置基线：原始空间、predictor-only、标准化、白化、固定差分；
- 消融：移除工况条件、移除显式分支、移除交互接口和匹配参数预算；
- 零假设：identity、random、label-shuffle、environment-label shuffle 和 candidate permutation。

### 7.8 指标与统计

- 主指标：留出工况 Top-K/排名、最差工况性能、故障信息保持、无关干扰残余可预测性和交互保真；
- 次指标：`delta/e/rho`、检测、校准、拒识、训练稳定性及计算成本；
- 使用跨种子配对层级 bootstrap、方法间块内置换和预注册非劣/优效比较；非劣界、最小有意义改善和种子数待 pilot 确定；
- 任何方法必须同时与 predictor-only 和固定变换比较，不以原始空间作为唯一基线。

### 7.9 通过、未通过与证据不足

- 某思想通过：在独立留出工况上超过前置对照的实际重要性阈值，保持故障信息与交互，不依赖标签置换或随机对照，且最差环境无不可接受退化。
- 全部未通过：无思想超过 predictor-only 或固定变换，或收益以故障信息损失为代价。
- 证据不足：不同指标形成未预注册的权衡、跨种子方向不一致、方法预算不匹配或 E2 数据条件不完整。

### 7.10 输出

- 文件：`method_family_manifest.json`、`budget_manifest.json`、`sample_metrics.jsonl`、`probe_predictions.jsonl`、`comparison_summary.json`、`decision.json`、`report.md` 和 `plots/`；
- 关键字段：思想族、实现版本、参数量、训练时长、种子、环境、逐样本预测、残余因素探针、故障保持和零假设结果；
- 图形：方法—环境森林图、Pareto 图、最差环境曲线、探针与诊断联合图。

### 7.11 结果分支

- 简单前置对照最佳：停止因素表示方法扩展；
- 单一思想稳定优胜：只保留该最小能力，进入 E4/E6；
- 组合仅在强交互场景优胜：限定适用范围，不推广到无交互场景；
- 结果不稳定：补充工况与拓扑重复，不据此选择具体方法。

### 7.12 代码复用与最小新增

- 可复用：现有训练器的固定早停、checkpoint、运行时记录，Z 路线一的 S/Z 双空间指标及零假设对照思想。
- 最小新增：统一方法族适配器、预算匹配器、留出环境评估、冻结表示探针和成对比较报告。具体表示模型不在本轮设计中确定。

## 八、E4：预测器与诊断几何瓶颈归因实验

### 8.1 命题、可验证内容与边界

- 对应命题：H4。
- 能够验证：失败主要来自信息不足、噪声覆盖、预测器误差、决策校准、固定距离尺度还是独立距离结构，并判断学习型诊断空间是否有必要。
- 不能验证：单次 Z Top-1 改善、单一 `R=Pr(rho_Z≤rho_S)` 或 Oracle 可分本身均不能证明 H4。

### 8.2 前置条件与分阶段进入门

- E0 已在本实验数据范围内通过；若 E0 判为信息不足或噪声覆盖，E4 只记录对应归因，不进入几何比较。
- E4-A 必须先完成原始空间、predictor-only、标准化、白化、固定差分和 calibration-only。
- 只有 E4-A 排除简单解释并出现剩余距离结构证据后，才允许另行确认低容量冻结预测器几何探针并进入 E4-B；本文不预选其方法。

### 8.3 数据、来源与新增需求

- 可复用：`data/s0-spb50`、阶段 A checkpoint、S0 报告、Z 路线一三种子报告、Oracle separability 和全候选预测；
- 必须新增：E0 噪声边界、有效分组清单、predictor-only 同预算训练、训练集拟合的标准化/白化/固定差分、验证集 calibration-only 及独立测试输出；
- 固定差分的参考必须在推理时可获得，例如同工况 NO_FAULT 基准或预故障窗口；参考来源和缺失处理必须冻结。

### 8.4 变量与交互项

- 自变量：预测器状态、表示/距离处理、决策校准、训练联合方式、噪声和工况；
- 因变量：`delta`、`e`、`rho`、候选错序率、真实候选排名、Top-K、检测、校准、拒识及 Oracle fidelity；
- 控制变量：数据、划分、预测器初始化、训练预算、候选集合、掩码、阈值选择数据和随机种子；
- 交互项：预测器×表示、表示×噪声、校准×阻抗和预测器×工况。

### 8.5 实验臂与配对

E4-A 依次执行：

1. clean/noisy Oracle，继承 E0；
2. 原始 S 空间冻结基线；
3. predictor-only：仅优化预测器；
4. 固定标准化；
5. 训练集白化；
6. 固定差分；
7. calibration-only：不改变预测或排序，只在验证集拟合阈值、概率和拒识规则；
8. 上述必要的 predictor×固定变换组合。

E4-B 仅在门通过后执行：冻结同一预测器，只施加另行确认的低容量诊断几何干预；随后与联合训练对照。所有实验臂在同一测试样本、候选和种子上成对比较。

### 8.6 划分与防泄漏

- 采用统一拓扑—工况分组；训练组拟合预测器及固定变换，验证组早停和校准，测试组一次性归因；
- 白化协方差、差分参考统计和 calibration 参数不得读取测试数据；
- E4-B 的几何探针若依据 E4-A 测试结果设计，则必须使用新的确认测试集，原测试集降级为开发集。

### 8.7 基线、消融与零假设

- 必备基线：原始 S、predictor-only、标准化、白化、固定差分和 calibration-only；
- 学习几何消融：冻结预测器与联合训练、移除几何目标、相同参数预算；
- 零假设：identity、random、label-shuffle、candidate permutation，并保留既有路线一作为已知未通过对照；
- 不允许只与原始 S 比较，也不允许仅依赖 R 指标。

### 8.8 指标与统计

- 每个故障样本同时报告 `delta_S/delta_Z`、`e_S/e_Z`、`rho_S/rho_Z`、`Delta log e`、`Delta log delta`、错序和真实排名；
- 检测层报告 ROC-AUC、PR-AUC、灵敏度、特异度、正常误报、弱故障漏报、Brier、校准误差与风险—覆盖；
- 使用样本/工况/拓扑层级 bootstrap、成对置换和跨种子区间；二元错误用配对检验；多实验臂采用预注册层级比较；
- “主要改善比例”、非劣界、最小 `rho` 改善和允许 Oracle fidelity 变化均待 pilot 确定。

### 8.9 归因与判据

- 信息不足：E0 Oracle 未通过；
- 噪声覆盖：clean Oracle 通过但 gap-to-noise 未通过；
- 预测器瓶颈：predictor-only 对 `e/rho/排序/诊断` 的改善达到预注册阈值，而几何处理无独立增益；
- 决策校准瓶颈：排序基本正确，calibration-only 解释检测、概率或拒识的主要失败；
- 固定距离尺度瓶颈：标准化、白化或固定差分达到学习干预的同等效果；
- 独立距离结构瓶颈通过：E4-A 排除前述简单解释后，E4-B 在冻结预测器、多种子、独立测试中稳定改善 `rho`、错序和诊断，显著优于 predictor-only、固定变换及全部零假设，同时保持 Oracle fidelity；
- 未通过：E4-B 无独立增益，或收益由预测器更新、全局缩放、标签泄漏或 Oracle 破坏解释；
- 证据不足：归因臂预算不等、区间跨阈值、校准测试复用或不同瓶颈高度交互而数据不足。

### 8.10 输出

- 文件：`arm_manifest.json`、`checkpoint_manifest.json`、`sample_metrics.jsonl`、`candidate_metrics.jsonl`、`calibration_metrics.jsonl`、`attribution_summary.json`、`decision.json`、`report.md` 和 `plots/`；
- 关键字段：实验臂、预测器哈希、变换拟合组、校准版本、S/Z residual、`delta/e/rho`、排序、概率、拒识、Oracle fidelity、零假设分位及归因状态；
- 图形：`e` 对 `delta` 相图、`rho` 成对变化、候选排序翻转、校准图、风险—覆盖曲线和归因瀑布图。

### 8.11 结果分支

- 信息或噪声瓶颈：转向数据、观测与不确定性；
- predictor-only 最优：改进预测器，不设计学习型诊断空间；
- calibration-only 最优：保留表示，修正决策层；
- 固定变换足够：采用最简单固定表示；
- 独立距离结构瓶颈成立：才启动学习型诊断空间的具体方法设计，并以 E5 通过关系限制物理约束；
- 均无改善：保留 S 空间并审计目标、标签与数据覆盖，不扩大模型容量。

### 8.12 代码复用与最小新增

- 可复用：`src/trainer.py`、`src/eval.py`、`src/z_eval.py`、`src/z_losses.py`、`src/z_route1.py`、Z 扫描汇总与现有 checkpoint/运行时契约。
- 最小新增：同预算 predictor-only 入口；训练集拟合的标准化、白化和固定差分；验证集校准与拒识评估；统一实验臂编排及层级归因报告。E4-B 的具体几何模块须待 E4-A 门通过后另行设计。

## 九、E5：跨工况、跨拓扑物理关系复核实验

### 9.1 命题、可验证内容与边界

- 对应命题：H5，每条物理关系分别形成子命题。
- 能够验证：拓扑跳数、电气距离、局部邻域、hardest-negative 集中性、阻抗/严重程度单调性和排序稳定性是否跨工况、跨拓扑成立到足以作为候选约束。
- 不能验证：单拓扑相关、节点对数量很大或符合直觉均不能证明可作为训练约束；相关性也不等同于根因机制。

### 9.2 前置条件与进入门

- 候选关系、方向、适用条件和预期训练用途已预注册；
- 至少具有多个拓扑实例和两个拓扑族；
- 关系发现拓扑与确认拓扑互斥；缺少独立拓扑时只能做 pilot。

### 9.3 数据、来源与新增需求

- 可复用：现有 proximity 流程、边属性、signature 距离、hardest-negative 和条件化字段；
- 必须新增：多拓扑/多族响应库、真实工况元数据、配对阻抗轨迹、拓扑级样本配额及独立确认拓扑；
- 现有 IEEE13、32 个故障样本和 20 次 Mantel 置换只作为流程证据，不进入 H5 正式通过判据。

### 9.4 变量与交互项

- 自变量：关系类型、拓扑族/实例、工况、故障类型、阻抗和观测率；
- 因变量：距离相关、最近邻命中、hardest-negative 邻近率、局部排序稳定、阻抗单调比例及诊断相关效应；
- 控制变量：故障类型、阻抗、工况和观测条件的配对；
- 交互项：关系×拓扑族、关系×故障类型、阻抗×工况和邻近×观测率。

### 9.5 生成与配对

- 在相同 `F 类型×阻抗×工况` 下比较候选节点对；
- 对同一位置/类型/工况生成阻抗轨迹；
- 对同一候选跨工况比较局部邻域和排序；
- 所有节点对嵌套于拓扑实例，不将节点对作为独立重复。

### 9.6 划分与防泄漏

- 发现集合只用于选择关系、效应方向和阈值；确认集合按拓扑实例或拓扑族互斥；
- 若确认后据结果修改关系，必须使用新的确认拓扑；
- E5 数据不得与后续使用该关系训练的测试拓扑重叠。

### 9.7 基线、消融与零假设

- 基线：拓扑跳数、电气距离、结构距离和无约束 signature 距离；
- 消融：全节点/观测节点、按故障类型/阻抗/工况条件化、局部/全局关系；
- 零假设：节点标签同步置换、保持度分布的随机拓扑、随机节点邻居、阻抗顺序置换和工况内候选排序置换。

### 9.8 指标与统计

- 相关关系报告 Spearman、Kendall、Mantel 及 Monte Carlo 误差；邻域关系报告命中率与随机基线差；单调关系报告配对单调比例和偏离量；
- 以拓扑实例为 bootstrap 单位，拓扑族为外层分层；预注册关系用 Holm 校正；
- 置换次数待 pilot 根据最小可分辨 p 值与 Monte Carlo 标准误确定；诊断相关效应阈值待 pilot 根据加入/不加入该关系时的敏感性分析确定，但不得使用确认测试拓扑选择。

### 9.9 通过、未通过与证据不足

- 单条关系通过：具有明确物理依据，在独立拓扑和工况上方向一致，效应达到冻结的诊断相关阈值，多重校正后成立，且不会排除 E0 已确认的弱故障信息。

- 证据不足：独立拓扑数不足、置信区间过宽、物理机制不明确或只在探索集合成立。

- 图形：拓扑族森林图、距离分箱图、矩阵热图、最近邻网络图、阻抗轨迹和排序稳定图。

### 9.11 结果分支

## 十一、E7：阈值、不确定性和独立数据验证实验

### 11.1 命题、可验证内容与边界

- 对应命题：H7。
- 能够验证：阈值、概率校准和拒识规则是否在独立数据上有效，以及已冻结方法对独立高保真仿真或真实系统数据的经验外推范围。
- 不能验证：只有内部仿真测试时不得宣称真实系统泛化；单一独立馈线也不能支持无边界的一般化结论。

### 11.2 前置条件与进入门

- E0–E6 已确定最终最小方法、适用域和失败场景；模型权重、候选集合、物理约束、阈值候选和拒识分数全部冻结；
- 独立验证数据来源、时间区间、馈线、传感器和标签质量已审计；
- 若没有真实数据，允许使用未参与方法开发的独立高保真仿真，但证据状态必须标为“仿真外部复核”，不能标为真实系统验证。

### 11.3 数据、来源与新增需求

- 阈值/校准集：与训练数据分组互斥的验证工况和拓扑，含正常与各阻抗故障；
- 独立测试：未参与方法选择的馈线、拓扑实例、运行周期或真实记录；
- 必须新增：标签质量、时间戳、传感器可用性、域来源、缺失机制及独立性证明；正常样本比例应反映目标应用或通过预注册重加权处理。

### 11.4 变量与交互项

- 自变量：域来源、阈值/校准策略、拒识覆盖率、场景、故障类型和阻抗；
- 因变量：ROC-AUC、PR-AUC、灵敏度、特异度、误报、漏报、Brier、校准误差、覆盖率、选择性风险和集合覆盖；
- 控制变量：冻结模型、表示、候选集合和数据预处理；
- 交互项：域×故障类型、域×阻抗、覆盖率×场景及观测率×校准。

### 11.5 生成与配对

- 校准集只用于选阈值、概率映射和拒识规则；
- 同一事件的窗口、派生观测和拓扑视图视为一个组；
- 真实或独立数据无法获得全候选反事实真值时，定位评价使用已确认标签，物理解释只报告可获得证据，不伪造 Oracle。

### 11.6 划分与防泄漏

- 按馈线、时间段、事件和运行周期分组；重叠窗口不得跨集合；
- 预处理统计量沿用训练数据，不在独立测试域重估；
- 独立测试只评估一次。任何调整后必须更换新的独立集合。

### 11.7 基线、消融与零假设

- 基线：零阈值历史规则、未校准分数、无拒识、predictor-only、固定变换及最终方法；
- 消融：只校准、只拒识、校准加拒识、域内与跨域；
- 零假设：标签置换、常数概率、类别先验预测、随机拒识和按置信度相反顺序拒识。

### 11.8 指标与统计

- 主指标由应用代价确定：目标灵敏度下的误报，或目标误报下的灵敏度；选择何者及目标值均待人工确认/pilot 冻结；
- 同时报告 ROC-AUC、PR-AUC、Brier、可靠性图、校准误差、风险—覆盖、拒识后错误率、集合覆盖与集合大小；
- 按事件/馈线层级 bootstrap 95% 区间，域间差异使用分组置换；稀有故障报告精确二项或适当事件级区间；
- 校准方法、分箱方式、最小覆盖率和可接受风险待 pilot 根据校准集与应用代价确定。

### 11.9 通过、未通过与证据不足

- 通过：冻结阈值、校准和拒识规则在独立数据上同时满足预注册检测/定位、校准和覆盖要求，且分层失败范围已报告。
- 未通过：独立数据上的关键安全指标区间完全越过失败界，或拒识不能降低选择性风险。
- 证据不足：真实标签质量不明、独立事件数不足、独立性被破坏，或只有内部仿真却试图支持真实系统结论。

### 11.10 输出

- 文件：`frozen_model_manifest.json`、`calibration_config.json`、`threshold_selection.json`、`independent_data_manifest.json`、`sample_metrics.jsonl`、`risk_coverage.jsonl`、`summary.json`、`decision.json`、`report.md` 和 `plots/`；
- 关键字段：数据域、事件组、标签质量、原始分数、校准概率、阈值、拒识分数、预测集合、覆盖、错误和适用域状态；
- 图形：ROC、PR、可靠性图、风险—覆盖、分层混淆和跨域森林图。

### 11.11 结果分支

- 通过：形成限定场景的最终证据包；
- 校准失败但排序有效：重新收集校准数据或采用更合适的决策层，不重训表示；
- 域偏移导致失败：补充目标域训练/适配数据并重新走 E4–E7，原独立集降级；
- 高不确定场景集中：收窄适用域或强制拒识；
- 无真实数据：只形成仿真外部复核结论，继续等待真实数据。

### 11.12 代码复用与最小新增

- 可复用：现有 residual `d`、逐样本预测、checkpoint 清单、评估和输出框架。
- 最小新增：验证集阈值/校准器、风险—覆盖与集合/拒识指标、时间/馈线分组、独立数据加载与标签审计、冻结模型清单。现有 `threshold=0` 和基础准确率/F1 不足以支持 H7。

## 十二、实验—命题—指标—判据—后续决策对应清单

### 12.1 E0 / H0

- 核心指标：Oracle Top-K、错序、`delta`、gap-to-noise、不可分对，以及 E0-COV 各模板覆盖臂的配对 rank 恢复；
- 通过要点：关键分层信息高于噪声边界；
- 后续：通过后先以 E0-COV 区分模板覆盖与候选本征混淆，再进入 E1；信息不足或噪声覆盖则转数据、观测、不确定性，不进入几何学习。

### 12.2 E1 / H1

- 核心指标：覆盖控制后的跨工况 rank/Top-K 翻转、`D_C/D_F/R_mix`、hardest-negative 转移、`P(j|i)` 及错排局部性；
- 通过要点：工况在模板覆盖控制后仍产生独立且实际重要的响应与排序影响；
- 后续：工况或交互通过时进入 E2；只存在覆盖效应时改进模板库；工况未通过时跳过因素路线并进入 E4-A；局部物理关系只送 E5 复核。

### 12.3 E2 / H2

- 核心指标：`Delta_F` 稳定性、子空间重叠、留出工况探针、`I_FC`；
- 通过要点：具备部分因素区分和跨工况复核条件；
- 后续：按可辨识程度决定 E3 可比较思想；共变不可分则补数据。

### 12.4 E3 / H3

- 核心指标：留出工况诊断、故障保持、残余干扰、最差环境、跨种子稳定；
- 通过要点：某思想超过 predictor-only、固定变换和零假设；
- 后续：选择最小思想能力，或全部回退简单基线。

### 12.5 E4 / H4

- 核心指标：`delta/e/rho`、错序、Top-K、校准、拒识和 Oracle fidelity；
- 通过要点：冻结预测器的几何干预在排除 predictor、固定变换、校准和零假设后仍有独立收益；
- 后续：只有此时设计正式学习型诊断空间，否则分别处理预测器、校准、固定尺度、噪声或数据。

### 12.6 E5 / H5

- 核心指标：拓扑级相关、Mantel、邻域命中、单调性、跨拓扑方向一致；
- 通过要点：单条关系在独立拓扑确认且具有诊断相关效应；
- 后续：通过关系可作为候选约束并做消融；其余只作描述。

### 12.7 E6 / H6 系列

- 核心指标：各场景 Oracle、`e/rho`、检测、定位、校准、拒识、最差环境和组合交互；
- 通过要点：各子命题分别满足信息层、稳定性层和模型层判据；
- 后续：确定适用域、补数据或回到 E4 做场景归因。

### 12.8 E7 / H7

- 核心指标：独立数据 ROC/PR、校准、风险—覆盖、误报/漏报和集合覆盖；
- 通过要点：冻结决策规则在独立数据满足预注册目标；
- 后续：形成限定外推结论，或因校准/域偏移失败返回相应分支。

## 十三、数据与代码缺口清单

### 13.1 数据缺口

- 当前生成器只支持 S0，实际负荷乘数未持久化，`operating_condition_id` 缺失时以样本序号代替；无法支持 E1/E2 的正式工况归因。
- 当前动态窗口包含随机扰动，但没有将数值误差、窗口扰动和测量噪声拆分为独立、可重复来源。
- 当前数据为样本级随机 80/20 划分，缺少拓扑—工况—基础样本分组清单。
- 现有 S2 只有单一 50% 随机掩码 smoke；关键节点集合为启发式默认值，未独立确认。
- 现有 S3 只有一个拓扑组，`split_valid=false`。
- 现有 S4 通过过滤既有随机阻抗形成，未构造同位置/类型/工况的跨阻抗配对，高阻视图没有匹配正常样本。
- 缺少多个拓扑实例和至少两个拓扑族的正式响应库、独立 E5 确认拓扑及 E7 真实或独立高保真数据。

### 13.2 代码能力与缺口

- 已具备：IEEE13/37/123 OpenDSS 路径、S0 全候选生成、signature library 校验、S1/S2/S3/S4 视图、Oracle 指标、proximity、TCN/GNN/响应预测器、训练早停、checkpoint、基础评估、Z 路线一与零假设扫描。
- S1 当前 flip 仅对真实活动边翻转，基线边状态全为 1 时与删除边效果等价；尚不能表达错误新增边，也不能完整区分错误确定信息与未知状态。
- `A1ArrayDataset` 未向训练流程提供 `base_sample_id`、工况和拓扑组字段；训练器仍按样本随机划分并主要使用 S0。
- 现有 `eval.py` 仅提供基础 Top-K、检测准确率、召回、F1 和零阈值 residual 判断，缺少 ROC/PR、校准、拒识、置信区间和场景分组。
- 现有 Oracle bootstrap 默认按样本重采样，尚未实现拓扑/工况层级重采样；proximity 以单库平均矩阵为主。
- 缺少统一实验协议、数据/模型哈希、实验臂编排、paired statistics、多重比较和自动决策文件。

## 十四、推荐的最小实施批次

### 14.1 批次 M0：协议与共享数据契约

- 只实现协议清单、分组划分、工况持久化、随机源拆分和公共逐样本输出；
- 用现有 64 样本库做读取/写出兼容 pilot，不产生科学结论；
- 完成后才能开始正式数据生成。

### 14.2 批次 M1：E0 pilot 与正式样本量冻结

- 在 IEEE13 S0 的小型平衡物理块上生成数值、窗口和测量噪声重复；
- 估计 gap-to-noise 分布、重复数、正式样本量、bootstrap/置换次数和关键分层；
- 最小批次只回答 E0 能否进入正式确认，不同时启动学习型表示。

### 14.3 批次 M2：E0-COV 与 E1/E2 交叉 pilot

- E0 确认通过后，先完成 `C0/CR/CC/CRC` 模板覆盖配对消融和开发集覆盖密度曲线；
- 在覆盖控制下生成完整 `F×C` 交叉块，完成跨工况排序、故障—工况配对和错排局部性 pilot；
- 冻结 E0-COV 覆盖恢复界、E1 排序翻转/局部集中实际重要性阈值和 E2 可辨识性判据；
- 由结果决定是否存在 E3 的必要性。

### 14.4 批次 M3：E4-A 简单归因

- 只比较原始 S、predictor-only、标准化、白化、固定差分和 calibration-only；
- 若简单方案已解释失败，停止后续学习型几何实现；
- 只有出现剩余几何证据，才另立 E4-B 方法确认任务。

### 14.5 批次 M4：E5 与 E6 信息层扩展

- 生成多拓扑与配对阻抗数据；先完成 E5 独立关系复核、S2 多掩码 Oracle 和 S4 配对 Oracle；
- 同时使 S3 `split_valid=true`；
- 未通过的信息层场景不进入强制端到端定位目标。

### 14.6 批次 M5：条件方法、端到端场景与 E7

- 仅在相应门通过时执行 E3、E4-B、带验证物理约束的候选方法和 E6 模型层；
- 最终方法冻结后执行 E7；无独立数据时停止在“仿真外部复核”。

## 十五、预计配置、逐样本结果与报告文件

所有正式结果写入：

```text
code/method-a1/output/<experiment-id>/<run-id>/
```

每个运行至少包含：

- `config.json`：实验自变量、控制变量、交互、指标和软件版本；
- `data_manifest.json`：数据来源、分组、通道、单位、标准化和校验值；
- `split_manifest.json`：组级 train/val/test/independent 划分；
- `seed_manifest.json`：各随机过程种子；
- `sample_metrics.jsonl`：逐样本/逐视图预测、residual、排名、检测、概率、不确定性和组标识；
- `pair_metrics.jsonl` 或实验专用配对文件：逐配对效应与交互；
- `summary.json`：总体、分层、最差环境、区间和多重比较结果；
- `decision.json`：命题编号、`通过/未通过/证据不足`、触发判据、下一分支和禁止外推范围；
- `report.md`：实验目的、数据、方法、统计、结果、失败样本、证据等级、局限和后续决策；
- `plots/`：所有图形，图中注明样本数、独立统计单位、种子和配置哈希。

训练型运行另含 `checkpoint_manifest.json`、训练历史和运行时；Oracle 运行另含候选对与 hardest-negative 文件；校准运行另含阈值选择和风险—覆盖文件。最终结论只引用 `output/`，不引用 `checkpoint/` 作为交付证据。

## 十六、仍需人工确认或待 pilot 确定的事项

### 16.1 需人工确认

- 目标应用优先控制误报还是漏报，以及 E7 的操作点与错误代价；
- 目标测量噪声模型、传感器精度、时间同步误差和真实可获得工况变量；
- 候选粒度是否始终为母线级，以及不可分时允许的候选集合大小；
- S2 关键节点的工程约束与可部署传感器集合；
- S3 采用哪些拓扑族作为开发、确认和独立外推集合；
- E7 独立数据属于真实系统还是独立高保真仿真，以及标签可信度要求。

### 16.2 待 pilot 确定

- E0-COV 的模板工况数、阻抗覆盖密度、覆盖曲线停止点和配对 rank 恢复实际重要性界；
- E1 的正式交叉工况数、故障状态配额、rank/Top-K 翻转容许范围、`R_mix` 解读区间、母线宏平均稳定性界和局部错排集中界；
- E2 的子空间维数、探针容量、方向稳定性阈值和交叉单元配额；
- E3/E4 的非劣界、最小有意义改善、正式训练种子数和预算匹配容差；
- E5 的置换次数、诊断相关效应阈值和独立拓扑数量；
- S1 最差可接受退化，S2 各观测率通过界，S4 低/中/高阻范围与样本配额，以及组合场景交互界；
- E7 的校准方法、校准误差界、最小覆盖率、选择性风险界和独立事件数。

每个 pilot 必须使用专门的开发数据，并将所确定数值、估计方法、置信区间宽度和冻结时间写入 `decision_thresholds.json`。正式测试集不得用于补定上述数值。

### 16.3 E0 已由 pilot 确定、无需人工确认的事项

- 模板与评价阻抗网格、负荷工况数、数值和人为波形重复数、故障延迟覆盖、正式确认工况数、bootstrap 次数及距离计算批大小已经由独立 pilot 的覆盖稳定性与运行成本确定。
- 上述参数只对当前 E0 理想 IEEE13 范围有效；S2、S4、真实传感器噪声和跨拓扑实验必须重新 pilot，不得直接复用为正式参数。

## 十七、最终执行原则

Method-A1 的实验推进必须遵循以下顺序性约束：先证实信息存在且高于噪声，再用 E0-COV 排除模板覆盖不足，随后分析因素来源；先区分条件变量、无关干扰和交互，再比较因素处理思想；先完成 predictor-only、固定差分、标准化、白化和校准对照，再判断是否存在独立距离结构瓶颈；只有该瓶颈成立才设计学习型诊断空间；局部错排与物理邻近的关系只有经 E5 独立确认后才可进入训练约束；最后以 S1–S4、组合场景和 E7 独立数据完成限定适用域的验证。
