# Method-A1 PI predictor 扩大样本实验结论

## 1. 实验范围与固定条件

本实验在现有 PI predictor 实验基础上只调整事件样本数量：

- 原始规模：`160` 个事件。
- 扩大规模：`640` 个事件。
- 更大规模：`1600` 个事件。

除样本数量外，以下内容与原始实验保持一致：

- predictor 结构、输入输出字段和候选条件方式不变。
- `L_P`、`L_T`、`L_D` 定义和 `masked_node_normalized_mse` 响应距离不变。
- 标准化方法、`feature_scaler.npz` 统计量来源和 `node_scale` 截断范围不变。
- 评价指标、候选残差排序、physical gap 和 hardest-negative 定义不变。
- 训练超参数不变：`epochs=100`、`batch_size=16`、`lr=1e-3`、`patience=20`、`min_delta=1e-4`、`seed=342`，三个损失权重均为 `1.0`。
- 数据生成逻辑不变：OpenDSS 逐候选仿真、事件块计划、随机种子和标准化流程相同。
- 训练、验证、测试比例保持 `70%/15%/15%`，事件块大小保持 `4`，划分按物理事件块执行。

唯一代码层面的偏离是：`1600` 事件数据集首次契约检查因 float32 z-score 反算舍入失败，随后只调整了 paired-v1 契约检查中两处数值容差（均值和 `node_scale` 为 `5e-2`，标准差为 `2e-2`）。该调整不改变数据数组、标准化计算、划分、模型、损失、评价指标或训练超参数；失败和调整过程在下面第 5 节说明。

## 2. 独立运行标识与划分审计

原始 160 事件运行：

- 数据集 ID：`paired-v1-ieee13-seed342`。
- 运行 ID：`pi-response-full-20260919-seed342`。
- 划分：训练 `112`，验证 `24`，测试 `24`。

640 事件运行：

- 数据集 ID：`paired-v1-ieee13-640-seed342`。
- 运行 ID：`pi-response-full-20260920-640-seed342`。
- 划分：训练 `448`，验证 `96`，测试 `96`。

1600 事件运行：

- 数据集 ID：`paired-v1-ieee13-1600-seed342`。
- 成功运行 ID：`pi-response-full-20260920-1600-seed342-v2`。
- 划分：训练 `1120`，验证 `240`，测试 `240`。

三种规模均满足：训练、验证和测试索引互斥且并集覆盖全部事件；同一物理事件块不跨划分；比例均为 `0.70/0.15/0.15`。640 和 1600 数据集的契约检查均为 15 项全部通过，模型契约、回归检查和数值容差检查均通过。

## 3. 冒烟、估时与实际时间

小规模 smoke 使用 `32` 个 mock 事件、`16` 节点、`10` 个 epoch、三个变体，结果为：数据生成约 `0.59 s`，训练约 `9.72 s`，验证约 `0.61 s`，测试约 `0.07 s`，评估约 `0.56 s`，总墙钟约 `23.30 s`。

真实 OpenDSS 数据生成探针结果：`16` 事件约 `3.73 s`，折合 `0.233 s/事件`；`64` 事件约 `23.95 s`，折合 `0.374 s/事件`；原 `160` 事件正式运行约 `66.13 s`，折合 `0.413 s/事件`。估时采用最保守的 `0.413 s/事件`。

估时结果：

- 640 事件：脚本公式点估计约 `2007.75 s`；按原 160 事件实测训练的校准估计约 `607.7 s`。
- 1600 事件：脚本公式点估计约 `4974.34 s`；校准估计约 `1489.1 s`。

实际结果：

- 640 事件：数据生成 `277.26 s`，训练 `205.06 s`，验证 `19.84 s`，测试 `0.39 s`，评估 `0.58 s`，总墙钟 `507.05 s`；未超过估计时间，未发生超估时。
- 1600 事件：数据生成 `710.33 s`（在首次数据生成中测得，成功运行复用该数据集），训练 `651.20 s`，验证 `62.00 s`，测试 `0.93 s`，评估 `1.44 s`，训练与评估墙钟 `719.01 s`；数据生成与训练评估合计约 `1429.34 s`；未超过公式点估计 `4974.34 s`，未发生超估时。

运行期间 heartbeat 持续记录事件块、训练批次、epoch、验证阶段和评价阶段；主进程 CPU 时间、heartbeat 行数和输出文件持续增长；OpenDSS 在主进程内通过 COM 调用，没有发现独立 OpenDSS 子进程或文件锁等待。

## 4. 扩大样本后的结果

随机基线按故障候选数 `16` 计算：Top-1 为 `0.0625`，Top-3 为 `0.1875`，Top-5 为 `0.3125`。Oracle 真实候选 Top-1 为 `1.0`，平均真实 rank 为 `0.0`。

student 变体，学生部署路径：

- 160 事件：Top-1 `0.0833`，Top-3 `0.125`，Top-5 `0.25`，平均真实 rank `8.21`，response distance `0.00264`，physical-gap 相对误差 `1.223`，hardest-negative consistency `0.208`。
- 640 事件：Top-1 `0.0938`，Top-3 `0.2396`，Top-5 `0.3854`，平均真实 rank `6.77`，response distance `0.00336`，physical-gap 相对误差 `1.061`，hardest-negative consistency `0.0729`。
- 1600 事件：Top-1 `0.1333`，Top-3 `0.3958`，Top-5 `0.5417`，平均真实 rank `5.10`，response distance `0.00878`，physical-gap 相对误差 `1.144`，hardest-negative consistency `0.1167`。
- 训练轮数：160 事件实际 `98` 个 epoch，640 事件实际 `64` 个 epoch，1600 事件实际 `100` 个 epoch；三种规模均使用相同 patience 配置，早停触发时机不同。

teacher 变体，学生路径与教师路径：

- 160 事件：学生路径 Top-1 `0.125`，Top-3 `0.208`，Top-5 `0.333`，平均 rank `6.79`；教师路径 Top-1 `0.0833`，Top-3 `0.208`，Top-5 `0.375`，平均 rank `7.33`。
- 640 事件：学生路径 Top-1 `0.1458`，Top-3 `0.3542`，Top-5 `0.4896`，平均 rank `4.90`；教师路径 Top-1 `0.125`，Top-3 `0.333`，Top-5 `0.5417`，平均 rank `4.88`。
- 1600 事件：学生路径 Top-1 `0.1625`，Top-3 `0.45`，Top-5 `0.5708`，平均 rank `4.81`；教师路径 Top-1 `0.1792`，Top-3 `0.4292`，Top-5 `0.5875`，平均 rank `4.36`。

distill 变体：

- 160 事件：Top-1 `0.0417`，Top-3 `0.125`，Top-5 `0.1667`，平均 rank `7.58`。
- 640 事件：Top-1 `0.0833`，Top-3 `0.2396`，Top-5 `0.3646`，平均 rank `6.92`。
- 1600 事件：Top-1 `0.0833`，Top-3 `0.2542`，Top-5 `0.3875`，平均 rank `6.68`。
- distill 在 640 和 1600 事件上分别在第 `31` 和 `56` 个 epoch 触发早停，弱于同规模的 student 和 teacher 路径。

Top-5 由 `metrics_detail.json` 中已有的逐样本 `student_true_rank` 直接统计，评价流程未新增或修改指标定义。

## 5. 与原 160 事件结果的比较结论

指标是否随样本量改善：

- student 路径的 Top-1、Top-3、Top-5 和平均真实 rank 随事件数增加呈单次运行下的改善趋势：Top-1 从 `0.0833` 到 `0.0938` 再到 `0.1333`，Top-3 从 `0.125` 到 `0.2396` 再到 `0.3958`，Top-5 从 `0.25` 到 `0.3854` 再到 `0.5417`，平均真实 rank 从 `8.21` 到 `6.77` 再到 `5.10`。
- teacher 变体的学生路径和教师路径也呈改善趋势，1600 事件下教师路径 Top-1 约 `0.179`。
- distill 结果没有随样本量稳定改善，且早停轮数明显少于 student 和 teacher。

结果是否仍接近随机：

- 160 和 640 事件的 Top-1 仅略高于 `0.0625` 的随机基线，Top-3 和 Top-5 在 640 事件下已高于对应随机基线。
- 1600 事件的 Top-3 `0.3958` 和 Top-5 `0.5417` 明显高于随机基线 `0.1875` 和 `0.3125`，Top-1 `0.1333` 也高于 `0.0625`，但仍远低于 Oracle 的 `1.0`。
- 因此 1600 事件下不能再说结果“接近随机”，但 Top-1 仍然较弱。

预测误差是否仍影响候选排序：

- student 路径的 response distance 与 oracle physical gap 的比值分别为：160 事件约 `2.36`，640 事件约 `1.73`，1600 事件约 `5.64`。
- 三种规模下 response distance 均大于 oracle physical gap，说明学生响应误差仍然大于候选间真实分离度，预测误差继续限制候选排序。
- physical-gap 相对误差保持在约 `1.06-1.14`，hardest-negative consistency 保持在约 `0.04-0.21`，没有随样本量稳定收敛到可接受水平。
- 因此样本量增加改善了 Top-K 和平均 rank，但没有消除响应误差主导的排序瓶颈。

是否能够判断原结果受到样本数量影响：

- 单次规模对照显示原 160 事件结果的 Top-K 和平均 rank 偏低，样本量至少是限制因素之一；扩大事件数后排序指标改善。
- 但三种规模的 student 实际训练轮数分别为 `98`、`64` 和 `100`，早停时机不同；不同规模的数据分布和 `node_scale` 也随训练集变化。当前只有单一随机种子 `342`，不能把改善量完全归因于样本数量，也不能排除训练随机性影响。
- 因此只能表述为：原 160 事件结果可能低估了该配置的排序性能，但本轮单次规模对照不足以给出最终统计结论。

## 6. 结论

在本轮固定配置、单一随机种子和 IEEE13 单拓扑族条件下，扩大事件样本量后 student predictor 的 Top-1、Top-3、Top-5 和平均真实 rank 呈现改善趋势；1600 事件下 Top-3 和 Top-5 已明显高于随机基线，但 Top-1 仍然偏低，且学生 response distance 仍大于 oracle physical gap，预测误差继续影响候选排序。teacher 变体呈现类似改善，distill 变体未显示稳定收益。

该结果只能作为单次规模对照结论，不能写成最终统计结论。要判断样本量的真实效应，需要至少多种子、相同早停有效轮数或固定训练轮数的独立重复实验。
